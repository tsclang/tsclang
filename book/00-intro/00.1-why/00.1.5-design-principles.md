# 00.1.5 Принципы проектирования

Три принципа, которые определяют каждое решение в TSClang.

## П1. Кросс-платформенная верификация

Любое решение проверяется на то, как оно работает на **всех** целевых платформах:

- **Desktop** (libuv, full heap, threads)
- **Embedded/AVR** (no heap или static heap, no OS, cooperative scheduler)
- **Async/await** (state machine, borrow across await, generator)
- **Многопоточность** (threads, channels, Atomic, data races)

Если фича работает на desktop, но ломается на embedded — это баг, а не feature flag.

### Пример: Map<K,V>

```typescript
let m = new Map<string, i32>();
m.set("hello", 42);
console.log(m.get("hello"));
```

На desktop — heap-allocated хеш-таблица. На embedded — статическая хеш-таблица фиксированного размера. Код один и тот же, поведение одинаковое, но реализация адаптируется к платформе.

### Пример: String

```typescript
let s = "hello";
console.log(s.length);
```

На desktop — ARC (atomic reference counting), heap-allocated. На embedded — rodata/PROGMEM, zero allocation. Код один и тот же.

## П2. Максимальная совместимость с TypeScript

TSClang — TypeScript-подобный язык. Максимальное число вещей из TS должно работать:

- `async/await` — работает (на всех платформах, включая embedded)
- `Map<K,V>` — работает (с адаптацией для embedded)
- Строки, массивы, closures — работают везде
- Классы, интерфейсы, дженерики — работают

Если TS делает что-то определённым образом, TSClang должен делать так же — **если нет явной причины отклониться**. Причины для отклонения:

1. **Memory safety** — TS позволяет UB (use-after-free, null dereference), TSClang — нет
2. **Embedded constraints** — TS не работает без heap, TSClang — должен
3. **Performance** — TS использует GC и dynamic dispatch, TSClang — нет

## П3. TSClang лучше, чем TS/C/C++/Rust

Мы не делаем «ограниченный TS» или «удобный C». Мы делаем язык, который:

- **Безопаснее C/C++** — borrow checker, no UB, deterministic cleanup
- **Быстрее TS** — компилируется в нативный код, zero-cost abstractions
- **Проще Rust** — нет lifetime annotations, нет сложного borrow checker, но memory safety сохраняется
- **Работает на железе** — embedded, retro, bare metal — без исключений

Любое решение, которое делает язык *хуже* конкурентов в их сильных сторонах — пересматривается.

## Конфликт принципов

Принципы могут конфликтовать. Пример:

- П2 (TS compat) хочет `undefined` как синоним `null`
- П3 (лучше Rust) хочет `undefined` убрать совсем

Решение конфликта — через иерархию приоритетов. Безопасность памяти (П3) важнее TS-совместимости (П2). Но если можно удовлетворить оба — удовлетворяем оба.

## Верификация через книгу

Каждая фича в этой книге проверяется через П1–П3:

1. Работает ли на всех платформах? (П1)
2. Совместимо ли с TS-паттерном? (П2)
3. Лучше ли, чем в C/Rust? (П3)

Если хотя бы на один вопрос ответ «нет» — разбираемся, почему, и либо исправляем, либо документируем компромисс.
