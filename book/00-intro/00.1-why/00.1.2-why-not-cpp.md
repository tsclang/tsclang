# 00.1.2 Почему не C/C++

## C

C — прекрасный язык. Простой, быстрый, портативный. Но у него есть проблемы, которые невозможно исправить обратно совместимым образом.

### Undefined Behavior

```c
int arr[4] = {1, 2, 3, 4};
int x = arr[10]; // UB — может сделать что угодно
```

Компилятор имеет право предположить, что UB не происходит, и оптимизировать код на основе этого предположения. Результат — непредсказуемое поведение в продакшене.

### Ручное управление памятью

```c
char* s = malloc(100);
// ... 200 строк кода ...
free(s);
// ... ещё 50 строк ...
printf("%s", s); // use-after-free — UB
```

Нет никаких гарантий. Забыл `free` — утечка. Освободил дважды — double free. Использовал после `free` — UB.

### Нет экосистемы

В C нет стандартного пакетного менеджера. Нет стандартной системы сборки (CMake — де-факто стандарт, но не часть языка). Нет стандартного формата модулей. Каждая библиотека делает по-своему.

## C++

C++ пытается решить проблемы C, но создаёт новые.

### Сложность

C++ — один из самых сложных языков программирования. Стандарт C++23 — более 2000 страниц. Правила вывода типов, overload resolution, template metaprogramming, move semantics, perfect forwarding — каждый из этих механизмов сложен сам по себе, а их комбинации порождают сюрпризы.

### Обратная совместимость

C++ тащит за собой все решения C, включая UB. `int* p = nullptr; *p;` — UB и в C, и в C++. Язык не может от этого избавиться, не сломав совместимость.

### Медленная компиляция

Шаблоны C++ — Turing-полная система. Компилятор может проводить минуты на инстанциации шаблонов. Это не оптимизация — это цена сложности.

## Что делает TSClang иначе

- **Нет UB** — каждый опасный паттерн либо запрещён, либо проверяется в compile-time
- **Автоматическая память** — ownership + borrow checker + RAII, без ручного `malloc`/`free`
- **Простая экосистема** — `tsclang build`, `tsclang install`, `tsc.package.json`
- **Быстрая компиляция** — нет template metaprogramming, монорфизация простая
