# 00.3.1 Конвейер компиляции

TSClang компилирует исходный код `.tsc` в C-код `.c` через последовательность фаз:

```
Исходный код (.tsc)
    │
    ▼
┌─────────┐
│  Lexer   │  Текст → токены
└────┬─────┘
     │
     ▼
┌─────────┐
│  Parser  │  Токены → AST
└────┬─────┘
     │
     ▼
┌──────────────┐
│ Optimizer    │  (опционально) AST → оптимизированный AST
└────┬─────────┘
     │
     ▼
┌──────────────┐
│  Decorator   │  AST → трансформированный AST (декораторы)
│  pass        │
└────┬─────────┘
     │
     ▼
┌──────────────┐
│  Typecheck   │  (inline) проверка типов + ownership
└────┬─────────┘
     │
     ▼
┌──────────────┐
│  Codegen     │  AST → C-код
└────┬─────────┘
     │
     ▼
C-код (.c) + CMakeLists.txt
```

## Порядок в коде

В текущей реализации:

1. **Lexer** (`src/compiler/lexer.js`) — разбивает текст на токены
2. **Parser** (`src/compiler/parser.js`) — строит AST из токенов
3. **Optimizer** (`src/compiler/optimizer.js`) — оптимизирует AST (опционально, по запросу)
4. **Codegen** (`src/compiler/codegen.js`) — обходит AST и генерирует C

Typecheck и decorator pass выполняются **inline** внутри codegen, а не отдельными фазами. Это текущее состояние — в будущем они будут выделены в отдельные проходы.

## CLI

```bash
tsclang build hello.tsc --outDir dist
```

Что происходит:
1. Читает `hello.tsc`
2. Лексер → токены
3. Парсер → AST
4. Codegen → C-код
5. Записывает `dist/hello.c`
6. Генерирует `dist/CMakeLists.txt` (если не существует)
