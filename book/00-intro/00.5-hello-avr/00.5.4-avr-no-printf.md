# 00.5.4 printf на AVR

## TSClang генерирует printf

TSClang-компилятор генерирует `printf` для `console.log` на всех платформах, включая AVR:

```c
printf("count: %g\n", 3.0);
```

Код на TSClang один и тот же:
```typescript
console.log("count:", 3);
```

## Что происходит на AVR

Когда avr-gcc компилирует этот C-код:

1. **avr-libc** предоставляет минимальную реализацию `printf`
2. Без флага `-lprintf_flt` — `%f` и `%g` **не работают** (выведут `?`)
3. С флагом `-lprintf_flt` — `%f` работает, но добавляет ~2-4KB flash
4. Базовый `printf` без `%f` занимает ~1KB flash

На ATmega328p — 32KB flash, 2KB SRAM. Это ощутимо.

## Альтернатива: прямой UART-вывод

Если flash критичен, можно обойтись без `printf`:

```typescript
@embedded.inline
function uart_print(s: string): void {
    native {
        for (size_t i = 0; i < s.length; i++) {
            while (!(UCSR0A & (1 << UDRE0)));
            UDR0 = s.data[i];
        }
    }
}
```

Побайтовый вывод через UART. Детерминировано, компактно (~50 байт flash).

## Рекомендация

- Для прототипирования — `printf` работает, удобен
- Для продакшена на AVR — прямой UART-вывод через `native {}` или специализированные функции
- TSClang генерирует portable C — оптимизация на уровне платформы — задача программиста
