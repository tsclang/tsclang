## Операторы

> Spec status: unverified · #205

### Арифметические

| Оператор | Описание |
|----------|----------|
| `+` | сложение; для `string` — конкатенация |
| `-` | вычитание |
| `*` | умножение |
| `/` | деление |
| `%` | остаток от деления |
| `**` | возведение в степень — всегда через `pow()` из `math.h`, результат `f64`. Для integer-операндов требуется явное приведение: `a ** b as i32` |
| `++` | инкремент (prefix / postfix) |
| `--` | декремент (prefix / postfix) |

### Присваивание

| Оператор | Эквивалент |
|----------|------------|
| `=` | присваивание |
| `+=` | `a = a + b` |
| `-=` | `a = a - b` |
| `*=` | `a = a * b` |
| `/=` | `a = a / b` |
| `%=` | `a = a % b` |
| `**=` | `a = a ** b` |
| `&=` | `a = a & b` |
| `\|=` | `a = a \| b` |
| `^=` | `a = a ^ b` |
| `<<=` | `a = a << b` |
| `>>=` | `a = a >> b` |
| `>>>=` | `a = a >>> b` |
| `&&=` | `a = a && b` |
| `\|\|=` | `a = a \|\| b` |
| `??=` | `a = a ?? b` |

### Сравнения

| Оператор | Описание |
|----------|----------|
| `==` | равенство; для смешанных скалярных категорий — неявная JS-коерсия + `W012` |
| `===` | строгое равенство; **никогда** не коерсит — смешанные категории = `E125` |
| `!=` / `!==` | неравенство; те же правила коерсии, что `==` / `===` соответственно |
| `<` `>` `<=` `>=` | сравнение чисел (и `char`) |

Правила по типам операндов:

| Выражение | Поведение |
|-----------|-----------|
| число == число (`i32==f64`, `char`, enum) | числовое сравнение, как есть |
| `bool == bool`, `string == string` | как в TS; строки — по содержимому (`tsc_string_eq`) |
| `T \| null` == `null`, `class == class` | null-check (`has_value`); идентичность ссылок — как в TS |
| смешанные скаляры через `==` | неявная коерсия ECMAScript Abstract Equality: `bool`→0/1, `string`→JS ToNumber (`"12px"`→NaN, `""`→0, `"0x1A"`→26), сравнение в `f64` + предупреждение `W012`; strict-правило `no-mixed-eq` → `E125`; decimal-типы (d8–d64) не коерсится никогда |
| смешанные скаляры через `===` | всегда `E125` — runtime-ответ смешанного `===` в TS/JS всегда `false` (TS даёт TS2367), коерсия расходилась бы с TS |
| `Array<T> == Array<T>` (T — примитив/string) | **по содержимому** (длина + поэлементно; IEEE для float: `-0.0==0.0`, `NaN!=NaN`) — семантика Rust `Vec` / C++ `vector`; осознанное расхождение с TS-ссылками: массивы здесь значения, идентичности не существует (то же решение, что для строк) |
| `Array<T> == Array<U>` (T≠U), `Array<Array<…>>`, `Array<class>` | `E126` |
| скаляр == `Array` / экземпляр класса | `E126` — у разнородных операндов нет осмысленного равенства |

> Коерсия в `==` повторяет TS/JS runtime, но скрывает смешение типов — поэтому помечается `W012`. strict-правило `no-mixed-eq` (см. §16) превращает её в жёсткую `E125`. Явное приведение остаётся рекомендуемым путём: `a.toString() == b`, `Number(flag) == 1`. Для контентного сравнения массивов из классов/вложенных — сравнивайте поэлементно (явная `deepEq`-функция в планах stdlib).

### Логические

| Оператор | Описание |
|----------|----------|
| `&&` | возвращает первый falsy операнд, или последний если все truthy |
| `\|\|` | возвращает первый truthy операнд, или последний если все falsy |
| `!` | логическое НЕ, возвращает `boolean` |
| `??` | возвращает правый операнд если левый `null` (не реагирует на `0`, `""`, `false`) |

Поведение `||` и `&&` аналогично JS — возвращают **сам операнд**, не `boolean`:

```typescript
const name = user.name || "Anonymous"   // string — "Anonymous" если name == ""
const port  = config.port || 8080        // i32    — 8080 если port == 0
const value = a && b && c               // тип c  — c если все truthy, иначе первый falsy

// ?? vs || — разница:
const x = value ?? "default"   // "default" только если value == null
const y = value || "default"   // "default" если value == null, "", 0, false
```

Тип результата `||` и `&&` — компилятор выводит из операндов (должны быть совместимых типов).

### Битовые

| Оператор | Описание |
|----------|----------|
| `&` | побитовое И |
| `\|` | побитовое ИЛИ |
| `^` | побитовое XOR |
| `~` | побитовое НЕ |
| `<<` | сдвиг влево |
| `>>` | сдвиг вправо (знаковый) |
| `>>>` | сдвиг вправо (беззнаковый) |

### Прочие

| Оператор | Описание |
|----------|----------|
| `? :` | тернарный оператор |
| `?.` | optional chaining — обращение к полю/методу если не `null` |
| `...` | spread |

### Приоритет операторов

От высшего к низшему. Операторы на одном уровне — левоассоциативны, если не указано иное.

| Приоритет | Оператор(ы) | Ассоциативность |
|-----------|-------------|-----------------|
| 18 | `()` группировка | — |
| 17 | `.` `?.` `[]` вызов `()` | левая |
| 16 | `++` `--` (postfix) | — |
| 15 | `!` `~` `+` `-` (unary) `++` `--` (prefix) | правая |
| 14 | `**` | правая |
| 13 | `*` `/` `%` | левая |
| 12 | `+` `-` | левая |
| 11 | `<<` `>>` `>>>` | левая |
| 10 | `<` `<=` `>` `>=` | левая |
| 9 | `==` `!=` `===` `!==` | левая |
| 8 | `&` | левая |
| 7 | `^` | левая |
| 6 | `\|` | левая |
| 5 | `&&` | левая |
| 4 | `\|\|` `??` | левая |
| 3 | `? :` | правая |
| 2 | `=` `+=` `-=` `*=` `/=` `%=` `**=` `&=` `\|=` `^=` `<<=` `>>=` `>>>=` `&&=` `\|\|=` `??=` | правая |

> `??` нельзя смешивать с `||` или `&&` без явных скобок — ошибка компилятора:
> ```typescript
> a || b ?? c    // error: смешивание || и ?? требует скобок
> (a || b) ?? c  // ok
> a || (b ?? c)  // ok
> ```
