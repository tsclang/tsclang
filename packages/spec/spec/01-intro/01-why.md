# Зачем

## Проблема

**TypeScript компилируется в JavaScript.** JS — интерпретируемый язык с GC, не подходит для bare metal, embedded и системного программирования. Runtime overhead, паузы сборщика мусора, невозможность управления памятью на низком уровне.

**C — нет достойной экосистемы.** Нет менеджера пакетов, нет стандартного способа кросс-компиляции, ручное управление памятью без защиты от use-after-free и dangling pointers.

**Rust — безопасный, но сложный.** Крутая кривая обучения, сложный синтаксис для разработчиков из мира TypeScript. Lifetime-аннотации, borrow checker с явными аннотациями — барьер для входа.

## Решение

TSClang — компилируемый язык, объединяющий четыре столпа:

- **TypeScript как синтаксис** — TS-разработчик узнаёт конструкции и чувствует себя дома
- **C как цель компиляции** — генерируемый C-код читаемый, отлаживаемый, работает на любой платформе с C-компилятором
- **Rust как модель безопасности** — ownership, borrow checker, детерминированное освобождение памяти без GC
- **npm как опыт экосистемы** — менеджер пакетов, зависимости, кросс-компиляция через `@platform`

## Область применения

- Серверный код — HTTP, сокеты, бэкенд
- Десктопные приложения — CLI, TUI, GUI
- Системный уровень — драйверы, операционные системы
- Embedded — Arduino, ESP, STM32
- Игры — OpenGL, DirectX
- Ретро-платформы — NES, Genesis, ZX Spectrum

## Вне области

- **Замена TypeScript в браузере** — TSClang не компилируется в JavaScript, не предназначен для frontend-разработки в браузере
- **Замена Rust для safety-critical систем** — TSClang проще в изучении, но менее формально верифицируем
- **Полная бинарная совместимость с C-библиотеками без обёрток** — требуется `.d.tsc` декларация для каждого C-интерфейса
