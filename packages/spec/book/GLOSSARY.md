# Глоссарий TSClang

## A

### ARC (Atomic Reference Counting)
Механизм автоматического подсчёта ссылок на объект. Каждый раз, когда кто-то «держит» объект — счётчик увеличивается (retain). Когда перестаёт — уменьшается (release). Когда счётчик падает до нуля — объект освобождается. Атомарный — значит потокобезопасный (использует CPU-инструкции). В TSClang используется для `Shared<T>`.

### ASI (Automatic Semicolon Insertion)
Механизм JavaScript, автоматически вставляющий точку с запятой в конце строк. Часто приводит к неожиданному поведению. TSClang **не** использует ASI — точка с запятой опциональна через другой механизм: парсер определяет конец выражения по контексту.

### AST (Abstract Syntax Tree)
Абстрактное синтаксическое дерево. Структура данных, которую парсер строит из токенов. Каждый узел дерева — конструкция языка: переменная, функция, цикл, выражение и т.д. Codegen обходит AST и генерирует C-код.

## B

### BSS
Сегмент памяти в C-программе, где размещаются неинициализированные глобальные и статические переменные. Автоматически заполняется нулями при запуске. На AVR — важный ресурс, т.к. вся память ограничена.

### Bare metal
Выполнение кода непосредственно на процессоре, без операционной системы. Микроконтроллеры (AVR, STM32) работают в bare metal режиме. TSClang поддерживает bare metal через embedded-таргет.

### Borrow checker
Механизм компилятора, который проверяет правила заимствования: нельзя иметь мутабельную ссылку и другие ссылки на один объект одновременно (aliasing XOR mutability). В TSClang — проще, чем в Rust: нет lifetime-аннотаций, используется scope-based lifetime.

## C

### Cooperative scheduler
Планировщик задач, где каждая задача сама отдаёт управление (через `await`). В отличие от preemptive scheduler (ОС), не требует переключения контекста и работает на embedded без OS.

## D

### Deterministic cleanup
Освобождение ресурсов в предсказуемый момент — когда переменная выходит из scope. В отличие от GC, где момент освобождения неизвестен. В TSClang реализовано через RAII: компилятор генерирует `tsc_string_release` и `_free` вызовы в конце scope.

## E

### Event loop
Цикл обработки событий. На desktop — libuv (полноценный event loop с I/O, таймерами, сокетами). На embedded — простой poll loop (`while (!_done) { poll(); }`). Async/await в TSClang построен поверх event loop.

## F

### FFI (Foreign Function Interface)
Интерфейс вызова функций из другого языка. В TSClang — C interop через `native {}`, `.d.tsc` файлы, `declare function`.

### Flash (на AVR)
Постоянная память (энергонезависимая) на микроконтроллере. На ATmega328p — 32KB. Здесь хранится программа и строковые литералы (через PROGMEM). В отличие от SRAM — flash только для чтения во время выполнения.

## G

### GC (Garbage Collector)
Автоматический сборщик мусора. Работает в JavaScript, Java, C#. Периодически останавливает программу для поиска и освобождения недоступных объектов (GC pauses). TSClang **не** использует GC — память управляется через ownership + RAII.

## H

### Heap
Динамическая память. Выделяется через `malloc`, освобождается через `free`. На desktop — доступна. На embedded (AVR) — отсутствует или ограничена.

### Heap-allocated
Объект, размещённый в heap (через malloc). В TSClang — строки при конкатенации, динамические массивы. На embedded — heap недоступен, используются альтернативы (ring buffer, BSS).

## I

### Inline cache
Оптимизация в JIT-компиляторах (V8), которая кэширует типы объектов для ускорения доступа к свойствам. В TSClang не актуально — нет JIT, типы известны в compile-time.

## J

### JIT (Just-In-Time compilation)
Компиляция кода в машинные инструкции во время выполнения. Используется в V8, SpiderMonkey. TSClang использует AOT (ahead-of-time) компиляцию — весь код компилируется до запуска.

## M

### Monomorphization
Способ реализации дженериков: для каждого конкретного типа генерируется отдельная копия функции. `id<i32>(x)` и `id<string>(s)` становятся двумя разными C-функциями. В отличие от boxing (одна функция, типы в runtime-обёртках).

### Name mangling
Кодирование информации о типах в имя C-функции. `greet(who: string)` → `greet_string`. Позволяет перегрузке функций работать в C — разные типы параметров = разные C-имена.

### No-op (no operation)
Операция, которая ничего не делает. Например, `tsc_string_release` для строкового литерала — no-op (нет refcount, нет heap). TSC_INIT на embedded — no-op.

## O

### Ownership
Модель управления памятью: каждая переменная «владеет» своим значением. При присвоении — ownership перемещается (move). После move исходная переменная недоступна. В отличие от GC (автоматическое освобождение) и ручного управления (malloc/free).

## P

### Poll loop
Простой цикл, который вызывает функцию обработки до завершения. `while (!_done) { poll(); }`. На embedded — основной механизм async/await (нет event loop с I/O).

### PROGMEM
Макрос AVR-libc, размещающий данные во flash-памяти вместо SRAM. `PSTR("hello")` помещает строку в flash. Доступ — побайтовый через специальные функции. TSClang использует PROGMEM для строковых литералов на AVR через `STR_LIT`.

## R

### RAII (Resource Acquisition Is Initialization)
Паттерн из C++: ресурс выделяется при создании объекта, освобождается при разрушении. В TSClang — компилятор автоматически генерирует cleanup-код (`tsc_string_release`, `_free`) в конце scope.

### Ring buffer
Циклический буфер фиксированного размера. Когда буфер заполняется — запись начинается с начала, затирая старые данные. На AVR используется для строк при конкатенации (нет heap).

### Rodata (read-only data)
Сегмент памяти для неизменяемых данных. Строковые литералы (`"hello"`) размещаются в rodata. На desktop — в RAM через загрузчик. На AVR — в flash (PROGMEM).

### Runtime overhead
Дополнительные ресурсы (память, CPU), которые тратятся на поддержку среды выполнения. В JavaScript — GC, JIT, inline caches, hidden classes. В TSClang — минимальный overhead (только String ARC на desktop).

## S

### SRAM
Оперативная память (энергозависимая) на микроконтроллере. На ATmega328p — 2KB. Здесь размещаются переменные, стек, ring buffer. Очень ограничена — каждый байт на счету.

### State machine (SM)
Способ реализации async/await: функция превращается в struct (переменные) + функцию poll (логика). Каждый `await` — новая «точка останова» (case в switch). Позволяет приостановить и возобновить выполнение без стека.

### Stack
Стек вызовов. Локальные переменные, параметры функций, return address. Ограничен — на AVR может быть несколько сотен байт. Рекурсия может переполнить стек (stack overflow).

### Static allocation
Размещение данных в BSS или data-сегменте на этапе компиляции. Не требует malloc. На embedded — основной способ работы с памятью.

## U

### UB (Undefined Behavior)
Неопределённое поведение в C/C++. Когда программа делает что-то, что язык не определяет (выход за границы массива, use-after-free, разыменование NULL). Компилятор имеет право считать, что UB не происходит, и оптимизировать на этом основании. Результат — непредсказуемое поведение. TSClang **устраняет** UB через ownership и borrow checker.

## V

### Vtable (virtual table)
Таблица указателей на методы. Используется для динамического dispatch при работе через интерфейс. В TSClang — генерируется для классов, реализующих интерфейсы. На embedded — overhead (дополнительный указатель + косвенный вызов).

## Z

### Zero-cost abstraction
Абстракция, которая не добавляет runtime overhead по сравнению с ручным написанием низкоуровневого кода. Пример: `Ref<T>` в TSClang компилируется в обычный указатель — нулевая стоимость по сравнению с ручным использованием указателей в C.
