# 00.5.4 printf на AVR

## TSClang генерирует printf

TSClang-компилятор генерирует `printf` для `console.log` на всех платформах, включая AVR:

```c
printf("count: %s\n", tsc_dtoa(3.0));
```

Код на TSClang один и тот же:
```typescript
console.log("count:", 3);
```

## Числа не зависят от printf-float

Ключевой момент: **числовые аргументы** форматируются не через `%f`/`%g`, а через `tsc_dtoa` — функцию runtime, которая сама превращает `double` в строку в JS-стиле. Это значит, что классическая проблема avr-libc не возникает:

1. **avr-libc** предоставляет минимальную реализацию `printf`
2. Без флага `-lprintf_flt` — `%f` и `%g` **не работают** (выведут `?`) — но TSClang их для чисел и не использует
3. `tsc_dtoa` работает без float-printf и без heap (8 ротационных статических буферов)
4. Базовый `printf` для строк занимает ~1KB flash

На ATmega328p — 32KB flash, 2KB SRAM. Экономия существенна: `-lprintf_flt` добавил бы ~2-4KB.

## Альтернатива: прямой UART-вывод

Если flash критичен, можно обойтись без `printf`. Inline-C пишется native-шаблоном (backtick-строка с `${...}`-подстановкой C-имён — фигурных `native { }`-блоков в языке нет):

```typescript
function uart_print(s: string): void {
    native `
        for (size_t i = 0; i < ${s}.length; i++) {
            while (!(UCSR0A & (1 << UDRE0)));
            UDR0 = ${s}.data[i];
        }
    `;
}
```

`${s}` подставляет C-имя переменной — код попадает в C как есть. Побайтовый вывод через UART. Детерминировано, компактно (~50 байт flash).

## Рекомендация

- Для прототипирования — `printf` + `tsc_dtoa` работают, удобны
- Для продакшена на AVR — прямой UART-вывод через native-шаблон или специализированные функции
- TSClang генерирует portable C — оптимизация на уровне платформы — задача программиста
