# 00.5.3 Runtime для AVR

Runtime на AVR — минимальный. Нет heap, нет OS, нет threads.

## String на AVR

Строки хранятся двумя способами:

1. **PROGMEM (flash)** — строковые литералы. `capacity = 0`. Не занимают RAM.
2. **Ring buffer** — конкатенация, substring. `capacity > 0`. Занимают RAM.

Ring buffer — статический массив фиксированного размера (256 байт по умолчанию):

```c
#ifndef TSC_STR_POOL_SIZE
#define TSC_STR_POOL_SIZE 256
#endif
static char _tsc_str_pool[TSC_STR_POOL_SIZE];
```

При переполнении — ring wrap (начинает с начала). Это значит, что старые строки затираются новыми. На AVR это нормально — памяти мало, строки короткие.

Можно увеличить размер буфера:

```c
#define TSC_STR_POOL_SIZE 512
#include "runtime.h"
```

## Массивы на AVR

Массивы — стековые или BSS. Нет `malloc`/`realloc`:

```typescript
let arr: i32[] = [1, 2, 3];
```

Компилируется в фиксированный C-массив (статический анализ размера) или стековый массив.

## Map/Set на AVR

Статические хеш-таблицы фиксированного размера. `std/embedded` предоставляет `HashMap<K,V,N>` с compile-time размером.

## TSC_INIT

На AVR `TSC_INIT()` — no-op. Ring buffer position инициализируется через zero-init в BSS (`static size_t _tsc_str_pool_pos = 0;`), а не через TSC_INIT. Нет heap, нет потоков, нет event loop — нечего инициализировать.

## Почему printf работает на AVR

TSClang генерирует `printf` — но на AVR `printf` ведёт себя иначе:
- avr-libc предоставляет минимальную реализацию `printf` (без `%f` по умолчанию)
- Вывод направляется через UART (нужно инициализировать `USART`)
- Можно избежать `printf` полностью, используя прямой UART-вывод через `native {}`
