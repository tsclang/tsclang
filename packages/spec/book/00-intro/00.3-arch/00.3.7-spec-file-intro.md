## Файлы тестов

Тесты — основной источник истины. Каждый тест:

```
packages/tests/test/cases/<NN-section>/<feature>/<name>/
  input.tsc        — входной TSC-код
  expected.c       — ожидаемый C-output
  expected.out     — ожидаемый stdout (если runnable)
  expected.error   — ожидаемое сообщение об ошибке (если error)
```

17 секций + секция `book/` (примеры из этой книги), ~1860 кейсов. Примеры из книги живут в `packages/tests/test/cases/book/<блок>/<глава>/`.

## Связь: спецификация ↔ тесты ↔ реализация

```
packages/spec/spec/   → описывает, КАК должно работать
packages/tests/test/  → проверяет, КАК работает на самом деле
packages/compiler/src/ → реализация
```

Если spec и test расходятся — это баг. Либо spec неверен, либо реализация, либо тест.

## Эта книга

Эта книга — **новая спецификация**. Она заменяет `doc/` и дополняет `spec/`. Каждое утверждение в книге проверяется:

1. Против тестов — есть ли тест, подтверждающий это?
2. Против спецификации — что говорит spec?
3. Против реализации — что делает код?
4. На всех таргетах — desktop, embedded, async

Если три источника расходятся — разбираем через П1–П3.
