# 00.3.3 Парсер

Парсер — вторая фаза компиляции. Преобразует токены в AST (Abstract Syntax Tree).

## Вход

Токены от лексера:

```
let x : i32 = 42 ;
```

## Выход — AST

```json
{
  "kind": "VarDecl",
  "name": "x",
  "typeAnn": { "kind": "TypeRef", "name": "i32" },
  "init": { "kind": "Literal", "litType": "number", "value": "42" }
}
```

Все литералы — один узел `Literal` с полем `litType` (`number`, `string`, `boolean`, `null`, `int`, `char`, `bigint`) и строковым `value`.

## Узлы AST

Основные типы узлов:

| Узел | Описание |
|------|----------|
| `VarDecl` | Объявление переменной (`let x = 1`) |
| `FuncDecl` | Объявление функции |
| `ClassDecl` | Объявление класса |
| `Interface` | Объявление интерфейса |
| `Enum` | Объявление enum |
| `Return` | return-выражение |
| `If` | if / else |
| `For` | for-цикл |
| `ForOf` | for-of цикл |
| `While` | while-цикл |
| `Binary` | Бинарное выражение (`a + b`) |
| `Call` | Вызов функции (`f(x)`) |
| `Member` | Доступ к члену (`obj.field`) |
| `Literal` | Литерал (число, строка, boolean, null, char, bigint — различаются `litType`) |
| `TemplateLit` | Template literal (`` `hello ${name}` ``) |
| `ArrayLit` | `[1, 2, 3]` |
| `Arrow` | Стрелочная функция |
| `Await` / `Yield` | await / yield |
| `Import` | import-выражение |
| `Export` | export-выражение |

## Как работает

Парсер использует recursive descent:

1. Смотрит на текущий токен
2. Определяет, какой синтаксический конструкт начинается
3. Вызывает соответствующую функцию (parseVarDecl, parseFuncDecl, ...)
4. Возвращает узел AST

## Ошибки парсера

- Неожиданный токен: `let = 42` — ожидается идентификатор
- Незакрытая скобка: `function f(` — ожидается `)`
- Некорректный синтаксис: `class { }` — ожидается имя класса
