# 00.1.4 Философия TSClang

TSClang — это TypeScript-подобный язык, который компилируется в C. Формула:

**TypeScript как синтаксис. C как цель компиляции. Rust как модель безопасности. npm как опыт экосистемы.**

## Иерархия приоритетов

При любом дизайн-решении приоритеты в порядке убывания:

1. **Безопасность памяти** — ownership, borrow checker, no UB
2. **Производительность и типизация** — конкретные типы, zero-cost abstractions
3. **TS-синтаксис** — максимально сохранять, но не ценой п.1 и п.2

Это значит: если TS делает что-то небезопасно — TSClang отклоняется от TS. Если TS делает что-то неоптимально — TSClang тоже отклоняется. Но если можно сохранить TS-паттерн без ущерба для безопасности и производительности — он сохраняется.

## Принцип «TS-разработчик чувствует себя дома»

Цель не «существующий TS-код компилируется без изменений». Цель — «TS-разработчик узнаёт синтаксис и может начать писать за час».

```typescript
let a = 10
let a: number = 10
```

Оба варианта — валидный TSClang. Но TSClang добавляет конкретные типы:

```typescript
let a: i32 = 10      // 32-битное знаковое целое
let b: u8 = 255      // 8-битное беззнаковое
let c: f64 = 3.14    // 64-битное float (как number в TS)
```

## Принцип «C-бэкенд — это не костыль»

Компиляция в C — это осозненный выбор, а не ограничение. C — самый портативный язык в мире. Если существует C-компилятор для платформы — TSClang может работать на ней:

- Desktop (gcc, clang)
- Embedded (avr-gcc)
- Web (emcc / Emscripten)
- Retro (NES, ZX Spectrum, MS-DOS, Genesis, PS1/PS2)
- Любая платформа, для которой есть C-компилятор

## Принцип «Не добавлять фичи сверх необходимого»

TSClang не пытается быть «лучше Rust» или «лучше C++». Он пытается быть достаточным:

- Есть классы, интерфейсы, дженерики — для структурирования кода
- Есть ownership и borrow checker — для безопасности памяти
- Есть async/await — для асинхронного программирования
- Есть inline C и .d.tsc — для интеропа с C
- Нет: GC, reflection, macros, template metaprogramming, exceptions (в C++ смысле)

## Новые концепции через TS-синтаксис

Когда TSClang вводит концепцию, которой нет в TS, она выражается через TS-совместимый синтаксис:

| Концепция | Rust | TSClang |
|-----------|------|---------|
| Immutable borrow | `&T` | `Ref<T>` |
| Mutable borrow | `&mut T` | `Mut<T>` |
| ARC reference | `Arc<T>` | `Shared<T>` |
| Weak reference | `Weak<T>` | `Weak<T>` |
| Mutable parameter | `mut` в паттерне | `mut` ключевое слово (как в TS) |
| Readonly | нет | `readonly` (как в TS) |

`Ref<T>`, `Mut<T>`, `Shared<T>` — это generic-типы. Программисту на TS знакомы generic-типы (`Array<T>`, `Promise<T>`, `Map<K,V>`). Не нужно учить новый синтаксис.
