# 00.1.7 Сравнение TypeScript и TSClang

## Что совпадает

| Концепция | Синтаксис (TypeScript = TSClang) |
|-----------|-----------|
| Переменные | `let`, `const` |
| Функции | `function f() {}` |
| Стрелочные функции | `(x) => x + 1` |
| Классы | `class Foo {}` |
| Интерфейсы | `interface Bar {}` |
| Дженерики | `function id<T>(x: T): T` |
| Async/await | `async function f()` |
| Массивы | `number[]` |
| Map | `Map<string, number>` |
| Template literals | `` `Hello ${name}` `` |
| For-of | `for (const x of arr)` |
| Try/catch | `try { } catch (e) { }` |
| Console | `console.log()` |

## Что отличается

### Типы чисел

TypeScript: один тип `number` (= `f64`).

TSClang: конкретные типы.

```typescript
// TypeScript
let a: number = 42;

// TSClang
let a: number = 42;
let a: i32 = 42;
let b: u8 = 255;
let c: f64 = 3.14;
```

### Сравнение

В TSClang `==` и `===` идентичны — приведение разных типов отсутствует. `===`, однотипный `==` и `== null` переносятся как есть. Сравнение `==` между разными типами работает не как в TS — не полагайтесь на него. Используйте явное приведение типов.

TypeScript:

```typescript
let a = 1;
let b = "1";
console.log(a == b);
```

TSClang — явное приведение:

```typescript
let a = 1;
let b = "1";
console.log(a.toString() == b);
```

### Null и undefined

TypeScript: `null` и `undefined` — разные значения.

TSClang: `null` и `undefined` — TBD (один из спорных вопросов, будет разрешён в Block 2).

### Ownership

TypeScript: нет концепции ownership. GC собирает мусор.

TSClang: ownership + borrow checker.

```typescript
let s = "hello";
let s2 = s; // move — s больше нельзя использовать
```

### Тип ошибки

TypeScript: `any` в catch.

TSClang: `throws` в сигнатуре, типизированные ошибки.

```typescript
// TypeScript
function readFile(path: string): string {
    // может бросить что угодно
}

// TSClang
function readFile(path: string): string throws IOError {
    // бросает только IOError
}
```

### Модули

TypeScript: ES modules + namespaces + `declare global`.

TSClang: ES modules (только named exports, `export default` запрещён).

### Inline C

TypeScript: нет.

TSClang:

```typescript
native `
    printf("Direct C code!\n");
`
```

### Embedded

TypeScript: нет.

TSClang:

```typescript
// обработчик прерывания таймера — в TS нет
@isr("TIMER1_COMPA")
function onTick(): void {
    counter++;
}
```

## Что убрано

| Концепция | Почему убрана |
|-----------|--------------|
| `any` (свободный) | Небезопасно, но оставлен для interop |
| `eval()` | Невозможно в compile-time языке |
| Dynamic property access (`obj[key]`) | Небезопасно без reflection |
| `var` | Устаревшее, оставлено как alias для `let` |
| Prototype chain | Классы вместо прототипов |
| `this` binding rules | Упрощённая семантика `this` |

## Миграция

Простой TS-код часто работает как есть или требует минимальных правок:

```typescript
// TypeScript → TSClang: работает как есть
function add(a: number, b: number): number {
    return a + b;
}
console.log(add(2, 3));
```

Пример миграции с правками.

TypeScript — исходник:

```typescript
class Config {
    host: string;
    port: number;
    constructor(host: string, port: number) {
        this.host = host;
        this.port = port;
    }
}

function validate(cfg: Config): string {
    if (cfg.port < 1 || cfg.port > 65535) {
        throw new Error("port out of range");
    }
    return cfg.host + ":" + cfg.port;
}

const cfg = new Config("localhost", 8080);

console.log(validate(cfg));
console.log(cfg.port);
```

TSClang — правки:

```typescript
function validate(cfg: Ref<Config>): string throws Error {
    if (cfg.port < 1 || cfg.port > 65535) {
        throw new Error("port out of range");
    }
    return `${cfg.host}:${cfg.port}`;
}

let cfg = new Config("localhost", 8080);
```

Нужные правки:
- Добавить `throws` для функций, которые бросают ошибки
- Добавить ownership-аннотации (`Ref<T>`, `Mut<T>`) при необходимости
