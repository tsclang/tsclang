# 00.2.4 Быстрый старт

## Первый запуск — визард платформ

При первом запуске любой команды в интерактивном терминале (пока не существует
`~/.tsclang`) CLI показывает онбординг:

```
Welcome to tsclang! Set up platforms:
  [x] desktop    gcc + make + cmake
  [ ] avr        avr-gcc + avrdude
  [ ] wasm       emscripten
Select platforms (e.g. "1 3"; Enter = preselected; s = skip forever):
```

- **Enter** — ставит предвыбранный `desktop`; **«1 3»** или имена («desktop
  avr») — любой набор; **«s»** — пропустить навсегда.
- Выбранные платформы скачивают тулчейны в изолированный кеш
  `~/.tsclang/platforms/…` — та же механика, что у
  `tsclang platform install` (00.7.18): вопросы о скачивании и согласие
  машины описаны там же.
- Визард трогает только машинный уровень: файл проекта `tsc.package.json`
  не изменяется — пресеты билдов подключаются позже командой
  `tsclang platform install <имя>` в каталоге проекта.
- Любой исход пишет маркер `~/.tsclang/wizard.json` — визард не спрашивает
  повторно. Платформы, которых не оказалось в реестре, печатают
  `not available` и подсказку `install later: tsclang platform install <имя>`.

Без TTY (CI, пайпы) визард молча пропускается и ничего не пишет. Гейты:
`TSC_WIZARD=off` (или `0`) — полное отключение, `TSC_WIZARD_INTERACTIVE=1` —
форсировать в неинтерактивном окружении (тесты).

## init — создание проекта

```bash
tsclang init myapp
tsclang init mylib --library
tsclang init blink --avr
tsclang init mywrapper --declaration
```

`init myapp` (executable) создаёт структуру проекта:

```
myapp/
  tsc.package.json
  src/
    main.tsc
  test/
    main.test.tsc
```

`--library` — TSClang-библиотека (манифест + `index.tsc`), `--declaration` —
C-wrapper (манифест + рукописный `index.d.tsc`), `--avr` — executable под
микроконтроллер с конфигом прошивки. Шаблоны манифестов — 00.2.5.

## build — компиляция и запуск

```bash
tsclang build hello.tsc --emit exec
```

Компилирует в C, собирает бинарник системным gcc и сразу запускает его — без shell,
поэтому команда одинакова на Linux/macOS и Windows. Код выхода программы становится
кодом выхода CLI. Аргументы программы требуют shell-команды: `--emit binary --command "./hello arg1 arg2"`. Подробно — 00.7.2.

## build — компиляция

```bash
tsclang build hello.tsc --out-dir dist
```

Результат: `.c` файл (+ `CMakeLists.txt` если `--emit c`) или бинарник (если `--emit binary`).

## управление пакетами

```bash
tsclang install mylib
tsclang install mylib@1.2.3
tsclang remove mylib
```

`install <пакет>` дописывает зависимость в `dependencies` манифеста и пинит точную
версию в лок-файле `tsc.package.lock` (семантика npm; `i`/`u`/`r` — однобуквенные
алиасы install/update/remove). Реестр пакетов пока в разработке, поэтому загрузка
кода по имени не выполняется; уже работают: bare `tsclang install` — синхронизация
лок-файла с `dependencies`/`devDependencies` манифеста, `tsclang install file.tspkg`
— распаковка локального архива в `tsc_packages/`, и `tsclang remove <пакет>` —
удаление из манифеста, лок-файла и `tsc_packages/`. Подробно — 00.7.11–00.7.13.
