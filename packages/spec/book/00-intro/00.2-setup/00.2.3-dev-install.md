# 00.2.3 Установка для разработки

Пакет в npm (`npm install -g tsclang`, 00.2.2) публикуется редко и отстаёт от разработки. Установка из репозитория даёт CLI свежего коммита — она нужна, чтобы проверять последние изменения или участвовать в разработке самого компилятора.

## Требования

Всё из 00.2.1 (минимум — Node.js >= 18), плюс:

| Компонент | Версия | Зачем |
|-----------|--------|-------|
| git | любой | Клонирование репозитория |
| pnpm | >= 8 | Менеджер пакетов монорепозитория (`npm install -g pnpm`) |

gcc не обязателен: компиляция `.tsc` → `.c` не требует тулчейна, он нужен только для сборки бинарника (см. 00.2.1).

## Сборка и установка

```bash
git clone https://github.com/tsclang/tsclang.git
cd tsclang
git checkout develop        # основная ветка разработки
pnpm install
pnpm build
cd packages/cli
npm link
```

`npm link` создаёт глобальную команду `tsclang` как симлинк на `packages/cli/dist/` в вашей копии репозитория — это не копия, а живая ссылка.

Проверка:

```bash
tsclang --version
```

Вывод:

```
tsclang 0.1.0
```

## Почему develop, а не main

`main` — релизная ветка и обновляется редко (слив готовых изменений через PR); актуальный код живёт в `develop`. Установка из `main` даст состояние последнего релиза, из `develop` — текущую разработку.

## Обновление

Симлинк указывает в репозиторий, поэтому переустановка не нужна — достаточно подтянуть изменения и пересобрать:

```bash
git pull
pnpm build
```

## Запуск без глобальной установки

Из корня репозитория, без `npm link`:

```bash
pnpm tsclang        # собранная версия (dist/, после pnpm build)
pnpm tsclang:dev    # из исходников через tsx, без сборки
```

## Удаление

```bash
npm unlink -g @tsclang/cli
```

Примечание: глобальные пакеты привязаны к активной версии Node.js — после переключения версии (nvm, nvm4w, fnm) линк придётся сделать заново.
