# 00.2.5 Структура проекта

Все примеры ниже — точное содержимое файлов, создаваемых `tsclang init`
для соответствующего пресета (что команда печатает в консоль — 00.7.6,
справочник пресетов — там же).

## Executable

```
myapp/
  tsc.package.json    — конфигурация проекта
  src/
    main.tsc          — точка входа
  test/
    main.test.tsc     — самопроверяющийся тест (add(1, 1) = 2)
```

`tsc.package.json`:

```json
{
  "name": "myapp",
  "version": "0.1.0",
  "type": "executable",
  "main": "src/main.tsc",
  "builds": {
    "desktop": {
      "emit": "binary",
      "outDir": "build/desktop",
      "optimize": "O2"
    }
  },
  "scripts": {
    "start": "tsclang build --emit exec",
    "dev": "tsclang build --watch --emit exec"
  }
}
```

`tsclang run dev` — цикл разработки (watch + перезапуск), `tsclang run start` —
сборка и запуск.

Обязательные поля манифеста (проверяет `tsclang validate-config`):
- `name` — имя проекта
- `version` — семантическое версионирование (N.N.N)
- `type` — один из `executable | library | declaration | platform | package`
- `main` — точка входа (обязателен для `executable`)

## Library

TSClang-библиотека: исходник — `index.tsc`, декларации для потребителей
(`index.d.tsc`) — **генерируемый артефакт сборки**, как `.d.ts` у TS-библиотек
(руками их не пишут):

```
mylib/
  tsc.package.json
  index.tsc           — публичный API
```

`tsc.package.json`:

```json
{
  "name": "mylib",
  "version": "0.1.0",
  "type": "library",
  "builds": {
    "dts": {
      "main": "index.tsc",
      "emit": "dts",
      "outDir": "build/dts"
    }
  },
  "scripts": {
    "dts": "tsclang build --build dts"
  }
}
```

`tsclang run dts` генерирует `build/dts/index.d.tsc`. Отличия от executable:
нет поля `main` (entry — `index.tsc` по конвенции), `type` = `"library"`.

## C-wrapper (declaration)

Обёртка над C-библиотекой (`tsclang init sqlite3 --declaration`): `index.d.tsc` —
**рукописный исходник** (только `declare`-конструкции — функции, константы,
opaque types), ничего не генерируется:

```
sqlite3/
  tsc.package.json
  index.d.tsc         — declare function / declare const / declare opaque type
```

```json
{
  "name": "sqlite3",
  "version": "0.1.0",
  "type": "declaration"
}
```

## Минимальный проект

Минимальный TSClang-проект — один файл:

```
hello.tsc
```

```typescript
console.log("Hello, World!");
```

Компиляция:

```bash
tsclang build hello.tsc --out-dir dist
```

Никакой конфигурации не нужно — CLI работает и с одиночными файлами.

## С зависимостями

Зависимости ставятся в `tsc_packages/` — единый flat-список, как Cargo и Go,
без вложенных `node_modules`:

```
myapp/
  tsc.package.json
  src/
    main.tsc
  tsc_packages/
    mylib/
      tsc.package.json
      index.tsc
  tsc.package.lock
```

`tsc.package.json`:

```json
{
  "name": "myapp",
  "version": "0.1.0",
  "type": "executable",
  "main": "src/main.tsc",
  "dependencies": {
    "mylib": "^1.0.0"
  }
}
```

`tsc.package.lock` (поле `source` фиксирует происхождение пакета —
`registry` / `local` / git-URL):

```json
{
  "version": 1,
  "packages": {
    "mylib": {
      "version": "1.0.0",
      "source": "registry"
    }
  }
}
```

## Embedded-проект (AVR)

`tsclang init blink --avr` — executable для микроконтроллера: те же
`src/main.tsc` и `test/main.test.tsc`, но сборка под AVR:

```json
{
  "name": "blink",
  "version": "0.1.0",
  "type": "executable",
  "main": "src/main.tsc",
  "builds": {
    "avr": {
      "profile": "avr",
      "mcu": "atmega328p",
      "emit": "flash",
      "outDir": "build/avr",
      "optimize": "Os",
      "flash": {
        "programmer": "arduino",
        "port": "/dev/ttyUSB0",
        "baud": 115200
      }
    }
  },
  "scripts": {
    "flash": "tsclang build --build avr"
  }
}
```

`tsclang run flash` — сборка и прошивка через avrdude одной командой;
`flash.programmer` и `flash.port` поменяйте под свою плату.
