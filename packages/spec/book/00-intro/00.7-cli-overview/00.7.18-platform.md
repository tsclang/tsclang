# platform — платформы как пакеты

> Справочник CLI. Концепция и правила имён — в спецификации: `13-build.md`, разделы «Реестр» и «Подключение к проекту».

Платформа в TSClang — это **пакет из реестра**: gcc/msvc/avr/wasm — такие же пакеты, как любые чужие, просто официальные (`@tsclang/*`). Для работы с ними служит первая вложенная группа команд:

```
tsclang platform <command> [options]
```

| Подкоманда | Описание |
|------------|----------|
| `platform install <name>` | Установить платформу-пакет: `tsc_packages/`, запись в `dependencies`, builds/scripts из пресетов по правилам имён, предложение скачать тулчейны в `~/.tsclang/platforms/` |
| `platform search [query]` | Поиск по каталогу реестра платформ |
| `platform list` | Установленные платформы и состояние их тулчейнов |
| `platform remove <name>` | Удалить платформу и созданные ею записи манифеста (пользовательские правки не трогаются) |

## Поведение группы

```bash
$ tsclang platform            # help группы, exit 0
$ tsclang platform --help     # тот же help
$ tsclang platform install --help   # справка подкоманды
$ tsclang platform frobnicate
tsclang: unknown platform command 'frobnicate'   # exit 1
$ tsclang platform list --bogus
tsclang: unknown option '--bogus' for 'platform list'   # exit 1
```

- Неизвестная подкоманда и неизвестная опция — разные ошибки; обе громкие (exit 1).
- Флаги валидируются по подкоманде: `platform install` и `platform list` имеют собственные наборы опций.
- У группы нет однобуквенных алиасов и нет собственных опций.

## platform search и platform list

`search` читает каталог реестра v1 (JSON, репозиторий tsclang) и печатает совпадения
с явным типом записи:

```bash
$ tsclang platform search zxdev
Found 1 package matching "zxdev":
  @nes/zxdev@0.3.1 [platform] — ZX Spectrum dev platform (z88dk)

$ tsclang platform search frobnicate
No platforms found matching "frobnicate"   # exit 0 — пустой результат не ошибка
```

- Запрос — подстрока (без учёта регистра) по имени и описанию; без запроса — весь каталог.
- `--offline` (или env `TSC_NO_NETWORK`) — не ходить в сеть: свежий кэш используется,
  при его отсутствии тихий отказ — notice в stderr и пустой результат с exit 0.
- Env `TSC_REGISTRY` — путь к локальному каталогу-файлу или URL (для тестов и зеркал).
- Кэш каталога: `~/.tsclang/platform-catalog-cache.json`, TTL 5 минут; env
  `TSC_CATALOG_CACHE` переопределяет путь.

`list` сканирует `tsc_packages/` текущего проекта и печатает пакеты с
`type: "platform"` (обычные библиотеки не показываются):

```bash
$ tsclang platform list
@nes/zxdev@0.3.1  profile: zxdev  toolchains: z88dk

$ tsclang platform list
No platforms installed (see tsclang platform search)
```

## platform install

`install <имя>` находит пакет в каталоге реестра, скачивает `.tspkg` (sha256
проверяется, когда каталог его даёт), распаковывает в `tsc_packages/<имя>/`,
дописывает `dependencies` и применяет пресеты `builds`/`scripts` по правилам
имён (docker-модель):

```bash
$ tsclang platform install @nes/zxdev
Installed @nes/zxdev@0.3.1
  + build nes:zxdev
  + script nes:zxdev:dev
```

- Ошибки громкие (exit 1): имени нет в каталоге, пакет не платформа
  (`type` — факт из каталога), sha256 не сошёлся, офлайн без кэша каталога.
- Установка вне проекта создаёт минимальный `tsc.package.json` (npm-семантика).
- **Записи никогда не перезаписываются.** Lock (`tsc.package.lock`) хранит
  sha256-снапшот каждой записи, созданной платформой (`platform.builds/.scripts`),
  плюс `resolved`/`integrity` архива. Конфликт с ручной записью: не-TTY —
  пропуск с notice; TTY (env `TSC_PLATFORM_INTERACTIVE=1` форсирует) —
  подтверждение пропуска, явный отказ прерывает установку до записи манифеста.
- Повторная установка идемпотентна (без изменений манифест и lock не меняются);
  обновление до новой версии: свои нечёсаные записи обновляются, новые
  дописываются, исчезнувшие свои убираются, пользовательские (в т.ч. правленые
  бывшие свои) не трогаются.
- Скачивание тулчейнов в `~/.tsclang/platforms/` — отдельный шаг (#270);
  системные тулчейны работают уже сейчас.

## platform remove

`remove <имя>` удаляет платформу, но чистит только созданное ею — по
снапшотам из lock:

```bash
$ tsclang platform remove @nes/zxdev
tsclang: kept builds.nes:zxdev — you edited it (left in place)
Removed @nes/zxdev
  ! build nes:zxdev kept — edited by you
  - script nes:zxdev:dev (platform entry removed)
```

- Hash снапшота совпал — запись удаляется из `builds`/`scripts`; не совпал
  (пользователь правил) — остаётся, warning в stderr.
- Запись в `dependencies`, каталог `tsc_packages/<имя>/` и запись в lock
  удаляются; опустевшие maps не остаются в манифесте.
- Платформа не установлена — `not installed`, exit 1. Вопросов remove не
  задаёт: безопасен в не-TTY (CI, пайпы).

## Статус реализации

Все четыре подкоманды реализованы: `search`/`list` (реестр v1, кэш,
офлайн-гейты), `install` (скачивание `.tspkg`, builds/scripts по правилам
имён, lock-владение), `remove` (чистка по lock-снапшотам). Скачивание
тулчейнов — #270.
