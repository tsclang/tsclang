# platform — платформы как пакеты

> Справочник CLI. Концепция и правила имён — в спецификации: `13-build.md`, разделы «Реестр» и «Подключение к проекту».

Платформа в TSClang — это **пакет из реестра**: desktop (clang)/avr/wasm — такие же пакеты, как любые чужие, просто официальные (`@tsclang/*`). Для работы с ними служит первая вложенная группа команд:

```
tsclang platform <command> [options]
```

| Подкоманда | Описание |
|------------|----------|
| `platform install <name>[@spec]` | Установить платформу-пакет (версия по спеке — exact, диапазон `^ ~ >=` или latest без спеки): `tsc_packages/`, запись в `dependencies`, builds/scripts из пресетов по правилам имён, предложение скачать тулчейны в `~/.tsclang/platforms/` |
| `platform update [name]` | Обновить установленные платформы **в пределах спеки из `dependencies`** (без имени — все): диапазон — до новейшей версии внутри него; exact-версия — пин, не трогается; манифест без спеки (легаси) — до latest каталога. Новые пресеты дописываются, исчезнувшие убираются, ваши правки не трогаются; тулчейны новой версии качаются рядом со старыми (старые не удаляются — запиненные сборки продолжают воспроизводиться). Не-терминал без `--yes` только печатает доступные обновления — ничего не качает |
| `platform search [query]` | Поиск по каталогу реестра платформ |
| `platform list` | Установленные платформы и состояние их тулчейнов |
| `platform remove <name>` | Удалить платформу и созданные ею записи манифеста (пользовательские правки не трогаются) |

## Поведение группы

```bash
$ tsclang platform            # help группы, exit 0
$ tsclang platform --help     # тот же help
$ tsclang platform install --help   # справка подкоманды
$ tsclang platform frobnicate
tsclang: unknown platform command 'frobnicate'   # exit 1
$ tsclang platform list --bogus
tsclang: unknown option '--bogus' for 'platform list'   # exit 1
```

- Неизвестная подкоманда и неизвестная опция — разные ошибки; обе громкие (exit 1).
- Флаги валидируются по подкоманде: `platform install` и `platform list` имеют собственные наборы опций.
- У группы нет однобуквенных алиасов и нет собственных опций.

## platform search и platform list

`search` читает каталог реестра v1 (JSON, репозиторий tsclang) и печатает совпадения
с явным типом записи:

```bash
$ tsclang platform search zxdev
Found 1 package matching "zxdev":
  @nes/zxdev@0.3.1 [platform] — ZX Spectrum dev platform (z88dk)

$ tsclang platform search frobnicate
No platforms found matching "frobnicate"   # exit 0 — пустой результат не ошибка
```

- Запрос — подстрока (без учёта регистра) по имени и описанию; без запроса — весь каталог.
- `--offline` (или env `TSC_NO_NETWORK`) — не ходить в сеть: свежий кэш используется,
  при его отсутствии тихий отказ — notice в stderr и пустой результат с exit 0.
- Env `TSC_REGISTRY` — путь к локальному каталогу-файлу или URL (для тестов и зеркал).
- Кэш каталога: `~/.tsclang/platform-catalog-cache.json`, TTL 5 минут; env
  `TSC_CATALOG_CACHE` переопределяет путь.

`list` сканирует `tsc_packages/` текущего проекта и печатает пакеты с
`type: "platform"` (обычные библиотеки не показываются):

```bash
$ tsclang platform list
@nes/zxdev@0.3.1  profile: zxdev  toolchains: z88dk

$ tsclang platform list
No platforms installed (see tsclang platform search)
```

## platform install

`install <имя>[@спека]` находит пакет в каталоге реестра, резолвит версию по
спеке (#280), скачивает `.tspkg` (sha256 проверяется, когда каталог его даёт),
распаковывает в `tsc_packages/<имя>/`, дописывает `dependencies` и применяет
пресеты `builds`/`scripts` по правилам имён (docker-модель):

```bash
$ tsclang platform install @nes/zxdev
Installed @nes/zxdev@0.3.1
  + build nes:zxdev
  + script nes:zxdev:dev
$ tsclang platform install @nes/zxdev@^0.4   # диапазон — старшая внутри него
$ tsclang platform install @nes/zxdev@0.4.0  # exact — пин
```

- **Спека версии** (`#280`): exact (`0.3.1`), диапазон (`^0.4`, `~0.3.1`,
  `>=0.4`, `*`) или без спеки — latest каталога. Каталог несёт историю версий
  (`versions` в записи); prerelease-версии не резолвятся в диапазоны без
  prerelease (npm-правило).
- **dependencies хранит запрошенную спеку, lock — резолвнутую exact**
  (npm-семантика): bare-установка записывает каре от резолвнутой версии
  (`^0.3.1`), exact — саму точную версию (это пин для update). Повторная
  установка с другой спекой перезаписывает запись в `dependencies`.
- **minCli**: версия в каталоге может требовать минимальную версию CLI
  (`minCli`); требование новее текущего CLI — громкий отказ
  `requires tsclang >= <версия>`, exit 1. В диапазоне несовместимые по minCli
  версии тихо пропускаются (резолвится старшая совместимая); bare/`*`
  НЕ откатывается на старые — отказ громкий.
- Ошибки громкие (exit 1): имени нет в каталоге, пакет не платформа
  (`type` — факт из каталога), нет версии по спеке (со списком доступных),
  sha256 не сошёлся, офлайн без кэша каталога.
- `--offline` — не ходить в сеть (установка — операция записи: громкий отказ).
- Установка вне проекта создаёт минимальный `tsc.package.json` (npm-семантика).
- **Записи никогда не перезаписываются.** Lock (`tsc.package.lock`) хранит
  sha256-снапшот каждой записи, созданной платформой (`platform.builds/.scripts`),
  плюс `resolved`/`integrity` архива. Конфликт с ручной записью: не-TTY —
  пропуск с notice; TTY (env `TSC_PLATFORM_INTERACTIVE=1` форсирует) —
  подтверждение пропуска, явный отказ прерывает установку до записи манифеста.
- Повторная установка идемпотентна (без изменений манифест и lock не меняются);
  обновление до новой версии: свои нечёсаные записи обновляются, новые
  дописываются, исчезнувшие свои убираются, пользовательские (в т.ч. правленые
  бывшие свои) не трогаются.

## Тулчейны при установке

Тулчейны платформы скачиваются изолированно в
`~/.tsclang/platforms/<платформа>@<версия>/<тулчейн>@<версия>/` — мультиверсии
рядом, ничего не ставится в систему. Формат — единый `.tar.gz` (sha256
проверяется до распаковки, распаковывает системный `tar`). Официальные
платформы (`@tsclang/desktop`, `@tsclang/avr`, `@tsclang/wasm`) возят тулчейны
комплектом (#278): бандлы хостятся в GitHub-релизах профильных репозиториев
(`github.com/tsclang/platform-{desktop,avr,wasm}`, тег `toolchains-v1`),
собираются из официальных дистрибутивов (WinLibs gcc, LLVM/Clang на posix,
Zak's avr-gcc, avrdude, emsdk) переупаковкой в layout «`bin/`-наверху» с
файлом `TSC_BUNDLE_NOTICE.txt` (источник + лицензия). Матрица —
`win32-x64`, `linux-x64`, `darwin-x64`, `darwin-arm64` (на Intel-маках у
desktop — инструкция ставить clang из Xcode Command Line Tools: апстрим LLVM
не публикует darwin-x64; avr-gcc — brew-инструкцию); ОС без записи
в манифесте получает per-OS инструкцию.

```bash
$ tsclang platform install @nes/zxdev
Installed @nes/zxdev@0.3.1
  + build nes:zxdev
  + script nes:zxdev:dev
  toolchain z88dk: manual install — install z88dk manually: MSYS2 (…) or the vendor installer; …
  toolchain z88dk: downloaded to ~/.tsclang/platforms/nes-zxdev@0.3.1/z88dk@2.2.0
  toolchain z88dk: already installed (~/.tsclang/platforms/nes-zxdev@0.3.1/z88dk@2.2.0)
```

- Система не сканируется: PATH при установке не источник тулчейнов (#282) —
  платформа самодостаточна и возит свой изолированный бандл; уже скачан
  изолированно — используется, сеть не трогается.
- Нет скачанного — вопрос `[Y/n]` «скачать (~N MB)?»; ответ запоминается на
  машину (`~/.tsclang/toolchain-consent.json`). Отказ/не-TTY — печатная
  инструкция per-OS (MSYS2 / apt / brew).
- Env-гейты: `TSC_TOOLCHAINS=always` (качать без вопросов), `=never`
  (инструкция), `TSC_TOOLCHAIN_INTERACTIVE=1` (форсировать вопросы),
  `TSC_HOME` (корень `~` для тестов и CI-кэшей).
- Провал скачивания не валит установку: ошибка в stderr + инструкция.

## platform remove

`remove <имя>` удаляет платформу, но чистит только созданное ею — по
снапшотам из lock:

```bash
$ tsclang platform remove @nes/zxdev
tsclang: kept builds.nes:zxdev — you edited it (left in place)
Removed @nes/zxdev
  ! build nes:zxdev kept — edited by you
  - script nes:zxdev:dev (platform entry removed)
```

- Hash снапшота совпал — запись удаляется из `builds`/`scripts`; не совпал
  (пользователь правил) — остаётся, warning в stderr.
- Запись в `dependencies`, каталог `tsc_packages/<имя>/` и запись в lock
  удаляются; опустевшие maps не остаются в манифесте.
- Платформа не установлена — `not installed`, exit 1. Вопросов remove не
  задаёт: безопасен в не-TTY (CI, пайпы).

## Статус реализации

Все пять подкоманд реализованы: `search`/`list` (реестр v1, кэш, офлайн-гейты),
`install` (скачивание `.tspkg`, builds/scripts по правилам имён, lock-владение,
скачивание тулчейнов с согласием), `remove` (чистка по снапшотам), `update`
(#279). Semver-резолв версий (#280): каталог несёт историю `versions` +
`minCli`, `install <имя>@<спека>` резолвит exact/диапазон/bare, dependencies
хранят спеку (bare → каре от резолвнутой), lock — точную версию; `update`
ходит внутри диапазона, exact-пин не трогает. Сборка
потребляет изолированные тулчейны (#271, #282): кеш `~/.tsclang/platforms` —
единственный источник по умолчанию, PATH пробуется только для явного пина
`builds.<n>.toolchain` (`"name@version"` проверяет версию через `--version`),
capabilities `toolchain`/`toolchainFile`/`include` профиля задают имя и пути,
но PATH не разрешают; без кеша и без пина — ConfigError с инструкцией
install-or-pin. Подставляются в спавны и `CMakeLists.txt`. Скрипты платформ получают свои
пути и тулчейны через env `--command` (`TSC_C_FILE`, `TSC_TOOLS`,
`TSC_PLATFORM`; #272). Визард первого запуска (#274, 00.2.4) ставит тулчейны
выбранных платформ той же механикой — до диспетчера команд, один раз на машину.
Эталонная платформа `@tsclang/desktop` (#275) живёт в монорепо
(`packages/platforms/desktop`) и публикуется в in-repo каталог
(`packages/registry`): пресет `builds.desktop` (emit exec — gcc-сборка и
запуск), скрипты `desktop:start`/`desktop:dev`. Рядом в каталоге —
`@tsclang/avr` (пресет `avr`, emit hex + скрипт `avr:flash`) и
`@tsclang/wasm` (пресет `wasm`, emit wasm; профиль `wasm` существует только
в пакете, не в компиляторе). С версии 0.2.0 все три везут тулчейны комплектом
(#278): desktop — gcc (WinLibs; с 0.4.0 — clang/LLVM, симлинки gcc упразднены,
#282), avr — avr-gcc + avrdude, wasm — emcc; система при установке не
сканируется (#282) — качается изолированный бандл или печатается инструкция.
