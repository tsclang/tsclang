# 00.7.2 build — компиляция

## Синтаксис

```bash
tsclang build <input.tsc> [опции]
```

## Описание

Компилирует `.tsc`-файл. Результат зависит от `--emit`:

- `c` (по умолчанию) — `.c`-файл + `runtime.h` + `CMakeLists.txt` в каталоге вывода
- `binary` — исполняемый файл, собирается системным компилятором (gcc или clang)
- `hex`, `flash` — прошивка для embedded-таргетов (avr и др.)
- `wasm` — WebAssembly (Emscripten)
- `cmake` — только `CMakeLists.txt` в каталоге вывода, без компиляции `.c` (замена удалённой команды `build-cmake`)

Успешная компиляция кэшируется — повторный `build` без изменений берёт результат из кэша; `--no-cache` форсирует полную пересборку.

## Опции

| Опция | Аргумент | Описание | По умолчанию |
|-------|----------|----------|--------------|
| `--emit` | `c\|binary\|hex\|flash\|wasm\|cmake` | Формат вывода | `c` |
| `--out-dir` | `<dir>` | Каталог вывода | `.` (текущий) |
| `--target` | `<name>` | Целевая платформа: `desktop`, `avr`, `nes`, `wasm`, ... | `desktop` |
| `--platform` | `<profile>` | Встроенный профиль платформы: `arm`, `avr`, `avr-coop`, `avr-heap`, `desktop`, `dos`, `genesis`, `nes`, `ps2`, `spectrum`, `wasm`, `wasm32` | нет |
| `--build` | `<name>` | Именованная сборка из `tsc.package.json` | нет |
| `--mcu` | `<chip>` | Микроконтроллер: `atmega328p`, `atmega2560`, ... | нет |
| `--default-number` | `<type>` | Тип чисел по умолчанию: `f64`, `f32`, `i32`, ... | из профиля |
| `--allocator` | `<type>` | Стратегия аллокатора: `heap`, `static` | из профиля |
| `--async` | `<type>` | Модель async: `libuv`, `state_machine`, `none` | из профиля |
| `--strict` | `<rules>` | Strict-правила через запятую: `no-any`, `no-unsafe`, `no-native`, `safe-math`, `no-lossy-cast`, `no-dynamic-alloc`, `no-closures`, `no-sort` | нет |
| `--optimize` | `O0-O3\|Os\|Oz` | Уровень оптимизации | нет |
| `--debug` | — | Отладочная информация | нет |
| `--sourcemap` | — | Генерировать source map | нет |
| `--all-errors` | — | Показать все ошибки, без лимита | нет |
| `--watch` | — | Пересборка при изменении файлов | нет |
| `--no-cache` | — | Игнорировать кэш компиляции | нет |
| `--ram-size` | `<bytes>` | Лимит RAM для embedded-таргетов (проверки расхода памяти) | нет |
| `--stack-size` | `<bytes>` | Лимит стека для embedded-таргетов | нет |

## Именованные сборки

`--build <name>` берёт настройки из секции `builds.<name>` файла `tsc.package.json`:

```json
{
  "name": "myapp",
  "builds": {
    "avr": { "target": "avr", "mcu": "atmega328p", "emit": "hex" }
  }
}
```

Допустимые ключи сборки: `target`, `mcu`, `toolchain`, `toolchainFile`, `arch`, `emit`, `linkerScript`, `frequency` (синоним `freq`), `allocator`, `debug`. Опции командной строки переопределяют значения из профиля.

## Режим watch (`--watch`)

После сборки компилятор следит за всеми исходниками программы, включая импортированные файлы, и при изменении любого из них пересобирает проект:

```bash
tsclang build hello.tsc --watch
[22:41:03] Watching 3 files...
```

- Наблюдение — поллинг (`fs.watchFile`, интервал 200 мс); статусные сообщения с меткой времени пишутся в stderr.
- Набор отслеживаемых файлов обновляется после каждой пересборки: новые импорты подхватываются автоматически.
- Неизменённые модули берутся из кэша компиляции, поэтому пересборка после правки одного файла не перекомпилирует весь проект.
- Watch только пересобирает — запускать и перезапускать программу он не умеет; для запуска используйте `run` (00.7.3).

## Примеры

```bash
tsclang build hello.tsc                          # hello.c в текущем каталоге
tsclang build hello.tsc --out-dir dist            # dist/hello.c
tsclang build hello.tsc --emit binary            # исполняемый файл
tsclang build src/main.tsc --target avr --mcu atmega328p --emit hex
tsclang build src/main.tsc --build avr           # настройки из tsc.package.json
tsclang build hello.tsc --strict no-any,safe-math
tsclang build hello.tsc --watch                   # watch-режим
```

## Коды выхода

- 0 — успех (включая «нечего пересобирать» из кэша)
- 1 — ошибка компиляции, ошибка конфигурации, неизвестная опция
