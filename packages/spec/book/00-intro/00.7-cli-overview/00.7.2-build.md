# 00.7.2 build — компиляция

## Синтаксис

```bash
tsclang build <input.tsc> [опции]
tsclang b <input.tsc> [опции]  # алиас
```

## Описание

Компилирует `.tsc`-файл. Результат зависит от `--emit`:

- `c` (по умолчанию) — `.c`-файл + `runtime.h` + `CMakeLists.txt` в каталоге вывода
- `binary` — исполняемый файл, собирается системным gcc (требуется в PATH, clang пока не поддерживается; отсутствие — `ConfigError`)
- `exec` — `binary` + запуск собранного артефакта прямым spawn без shell (путь не зависит от платформы; код выхода программы → код выхода CLI)
- `hex`, `flash` — прошивка для embedded-таргетов (avr и др.); требуют `avr-gcc` и `avr-objcopy` в PATH, `flash` дополнительно `avrdude` (отсутствие — `ConfigError`)
- `wasm` — WebAssembly (Emscripten)
- `cmake` — только `CMakeLists.txt` в каталоге вывода, без компиляции `.c` (замена удалённой команды `build-cmake`)

Неизвестное значение `--emit` — ошибка (`ConfigError: unknown emit value '...'`), а не тихий fallback на `c`.

Успешная компиляция кэшируется — повторный `build` без изменений берёт результат из кэша; `--no-cache` форсирует полную пересборку.

## Опции

| Опция | Аргумент | Описание | По умолчанию |
|-------|----------|----------|--------------|
| `--emit` | `c\|binary\|exec\|hex\|flash\|wasm\|cmake` | Формат вывода | `c` |
| `--out-dir` | `<dir>` | Каталог вывода | `.` (текущий) |
| `--target` | `<name>` | Целевая платформа: `desktop`, `avr`, `nes`, `wasm`, ... | `desktop` |
| `--platform` | `<profile>` | Встроенный профиль платформы: `arm`, `avr`, `avr-coop`, `avr-heap`, `desktop`, `dos`, `genesis`, `nes`, `ps2`, `spectrum`, `wasm`, `wasm32` | нет |
| `--build` | `<name>` | Именованная сборка из `tsc.package.json` | нет |
| `--mcu` | `<chip>` | Микроконтроллер: `atmega328p`, `atmega2560`, ... | нет |
| `--default-number` | `<type>` | Тип чисел по умолчанию: `f64`, `f32`, `i32`, ... | из профиля |
| `--allocator` | `<type>` | Стратегия аллокатора: `heap`, `static` | из профиля |
| `--async` | `<type>` | Модель async: `libuv`, `state_machine`, `none` | из профиля |
| `--strict` | `<rules>` | Strict-правила через запятую: `no-any`, `no-unsafe`, `no-native`, `safe-math`, `no-lossy-cast`, `no-dynamic-alloc`, `no-closures`, `no-sort` | нет |
| `--optimize` | `O0-O3\|Os\|Oz` | Уровень оптимизации | нет |
| `--debug` | — | Отладочная информация | нет |
| `--sourcemap` | — | Генерировать source map | нет |
| `--all-errors` | — | Показать все ошибки, без лимита | нет |
| `--watch` | — | Пересборка при изменении файлов | нет |
| `--command` | `<cmd>` | Выполнить shell-команду после успешной сборки | нет |
| `--no-cache` | — | Игнорировать кэш компиляции | нет |
| `--ram-size` | `<bytes>` | Лимит RAM для embedded-таргетов (проверки расхода памяти) | нет |
| `--stack-size` | `<bytes>` | Лимит стека для embedded-таргетов | нет |

## Именованные сборки

`--build <name>` берёт настройки из секции `builds.<name>` файла `tsc.package.json`:

```json
{
  "name": "myapp",
  "builds": {
    "avr": { "target": "avr", "mcu": "atmega328p", "emit": "hex" }
  }
}
```

Допустимые ключи сборки: `target`, `mcu`, `toolchain`, `toolchainFile`, `arch`, `emit`, `linkerScript`, `frequency` (синоним `freq`), `allocator`, `debug`, `command` (пост-билд команда, см. ниже). Опции командной строки переопределяют значения из профиля.

## Пост-билд команда (`--command`)

`--command "<cmd>"` выполняет shell-команду после **успешной** сборки; если сборка провалилась — команда не выполняется. То же значение можно задать в манифесте: `builds.<name>.command` выполняется автоматически при `tsclang build <name>`, флаг `--command` перекрывает манифестное.

- Команду выполняет shell хоста: `cmd` на Windows, `/bin/sh` на Unix. Синтаксис платформозависим и лежит на совести автора команды (как `flash.programmer`/`flash.port`): на Windows путь к бинарю пишется с обратными слешами (`out\hello`) — cmd не понимает `./` и прямые слеши.
- Переменная окружения `TSC_OUT_DIR` содержит абсолютный путь к каталогу вывода: `%TSC_OUT_DIR%` в cmd, `$TSC_OUT_DIR` в sh.
- Разовая сборка: код выхода команды становится кодом выхода CLI.
- `--watch`: перед пересборкой дерево процессов прошлой команды завершается (`taskkill /T` на Windows, SIGTERM группе процессов на Unix), после успешной пересборки команда запускается заново. Провалившаяся пересборка не трогает работающий процесс.
- Команда не меняет `--emit` и не является ступенью emit: чтобы просто запустить собранный бинарь, есть ступень `--emit exec` (без shell и платформозависимых путей); `--command` — для произвольных команд и аргументов программы.
- Команда читается только из корневого `tsc.package.json` проекта — манифесты установленных зависимостей для сборок не читаются. Уровень доверия — «скрипты в собственном package.json».
- `--emit exec` + `--command` вместе — конфликт (`ConfigError: --emit exec already launches the built artifact`): exec сам запускает артефакт.

Запуск по таргетам:

| Таргет | Как запускать |
|--------|---------------|
| desktop | `--emit exec` — запуск собранного артефакта без shell (путь не зависит от платформы) |
| avr | `--emit flash` — прошивка через avrdude, команда не нужна |
| wasm | страница/движок подключает `.wasm` из каталога вывода; открыть: `--command "firefox %TSC_OUT_DIR%\hello.js"` |
| nes | эмулятор или картридж — через `--command` (в разработке) |


## Режим watch (`--watch`)

После сборки компилятор следит за всеми исходниками программы, включая импортированные файлы, и при изменении любого из них пересобирает проект:

```bash
tsclang build hello.tsc --watch
[22:41:03] Watching 3 files...
```

- Наблюдение — поллинг (`fs.watchFile`, интервал 200 мс); статусные сообщения с меткой времени пишутся в stderr.
- Набор отслеживаемых файлов обновляется после каждой пересборки: новые импорты подхватываются автоматически.
- Неизменённые модули берутся из кэша компиляции, поэтому пересборка после правки одного файла не перекомпилирует весь проект.
- Watch только пересобирает; автозапуск и перезапуск программы после пересборки — `--emit exec` или `--command` (см. выше).

## Примеры

```bash
tsclang build hello.tsc                          # hello.c в текущем каталоге
tsclang build hello.tsc --out-dir dist            # dist/hello.c
tsclang build hello.tsc --emit binary            # исполняемый файл
tsclang build src/main.tsc --target avr --mcu atmega328p --emit hex
tsclang build src/main.tsc --build avr           # настройки из tsc.package.json
tsclang build hello.tsc --strict no-any,safe-math
tsclang build hello.tsc --watch                   # watch-режим
tsclang build hello.tsc --watch --emit exec       # пересборка + перезапуск (dev-цикл)
tsclang build hello.tsc --emit binary --command "out\hello"      # win: запуск произвольной командой
tsclang build hello.tsc --command "echo $TSC_OUT_DIR"            # env (sh; в cmd — %TSC_OUT_DIR%)
```

## Коды выхода

- 0 — успех (включая «нечего пересобирать» из кэша)
- 1 — ошибка компиляции, ошибка конфигурации, неизвестная опция
- N — код выхода программы при `--emit exec` или пост-билд команды `--command` пробрасывается как код выхода CLI
