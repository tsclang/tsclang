# 00.7.17 doctor — диагностика окружения и проекта

## Синтаксис

```bash
tsclang doctor [--project] [--tools] [--fix]
```

## Описание

Одна команда, которая отвечает на вопрос «всё ли у меня готово для работы с TSClang»: платформа, версия CLI и её обновление, манифест проекта и рекомендуемые тулчейны. Конвенция имени — как `npm doctor` / `flutter doctor`.

Отчёт состоит из секций:

| Секция | Что проверяет |
|--------|---------------|
| Platform | ОС и архитектура |
| Version | Версия CLI и источник установки: глобальный npm или dev-линк (`npm link`, см. 00.2.3) |
| Update | Свежая ли версия на `registry.npmjs.org` (только для npm-установок) |
| Project | `tsc.package.json` в текущей папке: валидность (все проверки `validate-config`), наличие `main`-файла, недостающие `builds`/`scripts` против пресета `init` |
| Toolchains | Рекомендуемые тулчейны профиля проекта (desktop / embedded / wasm) |

## Метки и коды выхода

| Метка | Значение |
|-------|----------|
| `[ok]` | Всё в порядке |
| `[!]` | Проблема, которую можно починить |
| `[x]` | Отсутствует |
| `[~]` | Опционально — на exit-код не влияет |

Exit 0 — проблем нет; exit 1 — есть `[!]`/`[x]` по обязательным проверкам или диагностики манифеста. Успешно применённый фикс снимает проблему.

## Интерактивный режим

В терминале doctor спрашивает перед каждой секцией («Проверим ваш проект?», «Проверим рекомендуемые тулчейны? (профиль: desktop)») и предлагает каждый фикс тремя путями:

```
  [!] scripts missing: start, dev (preset executable/desktop)
     merge into tsc.package.json:
      "scripts": { ... }
  Добавить? (a)uto / (m)anual / (s)kip:
```

- **(a)uto** — применить автоматически: перед записью печатается превью, после — `fixed:`. Авто-фикс упал (права, файл заблокирован) → печатается причина и ручная инструкция, фикс не теряется.
- **(m)anual** — только ручная инструкция.
- **(s)kip** — пропустить.

Тулчейн «установлен, но не в PATH» (найден в типичных местах установки — `C:\msys64\mingw64\bin`, `C:\MinGW\bin`, emsdk и т.п.) предлагает добавить папку в PATH: автоматически на Windows (через PowerShell `[Environment]::SetEnvironmentVariable("Path", …, "User")` — никогда не `setx`, тот обрезает PATH до 1024 символов; нужен перезапуск терминала), на unix — только ручная `export`-инструкция: у каждого шелла свой rc-файл.

Без TTY (пайпы, CI) вопросы не задаются: тот же отчёт, а вместо вопросов — сразу ручные инструкции.

## Профили тулчейнов

Профиль выводится из `builds` манифеста (`emit: flash`/`hex` или `profile: avr` → embedded, `emit: wasm` → wasm, иначе desktop); без манифеста — desktop.

| Профиль | Обязательные | Опциональные |
|---------|--------------|--------------|
| desktop | gcc, cmake | gdb, msvc (только Windows) |
| embedded | avr-gcc, avr-objcopy, avrdude | — |
| wasm | emcc | — |

MSVC — особый случай: `cl.exe` почти никогда не лежит в PATH (ему нужны `INCLUDE`/`LIB` из vcvarsall), поэтому doctor не лечит его PATH-фиксом, а сообщает «VS найден, запускайте из Developer PowerShell». MSVC валиден как `toolchain` в CMake-флоу; прямой `--emit binary` остаётся за gcc.

## Обновление и сеть

`Update` — единственное сетевое обращение в CLI: `GET https://registry.npmjs.org/tsclang/latest` с таймаутом 3 секунды. Любой сбой (нет сети, таймаут, реестр недоступен) тихо печатает `check failed (offline?)` — отчёт никогда не падает из-за сети. Dev-установка печатает `npm check not applicable` (сравнение с реестром вводило бы в заблуждение). Локальная версия новее реестра читается как `up to date` — даунгрейд не предлагается.

## Опции

| Флаг | Описание |
|------|----------|
| `--project` | Только секция проекта |
| `--tools` | Только тулчейны |
| `--fix` | Применить манифест-фиксы без вопросов. PATH не трогает никогда — только явный интерактивный выбор |

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `TSC_DOCTOR_NO_UPDATE=1` | Не ходить в сеть за версией (`Update: skipped`) |
| `TSC_DOCTOR_INTERACTIVE=1` | форсировать интерактивный флоу под пайпом (CI/тесты) |

## Ограничения

- doctor не устанавливает тулчейны — печатает инструкцию (`winget`/`pacman`/`apt`, книга 00.2.1)
- пакеты (`tsc_packages/`) не проверяются — реестр пакетов пока mock
- без алиаса
