# 00.7.8 lint — линтер и форматтер

## Синтаксис

```bash
tsclang lint <input.tsc> [опции]
tsclang l <input.tsc> [опции]  # алиас
```

## Описание

Проверяет исходник встроенными правилами. Диагностики печатаются в stderr в формате:

```
LintWarning[prefer-const]: 'x' is never reassigned; use 'const' at line 3
LintError[no-unreachable]: unreachable code at line 12
```

Правила:

| Правило | Severity | Что ловит |
|---------|----------|-----------|
| `prefer-const` | warning | `let`, который никогда не переприсваивается |
| `no-unreachable` | error | Код после `return`/`throw` |
| `no-unused-var` | warning | Неиспользуемая переменная |

## Опции

| Опция | Форма | Описание |
|-------|-------|----------|
| `--fix` | флаг | Применить автоисправления к файлу на месте; неисправимые диагностики печатаются как обычно |
| `--format` | флаг | Отформатировать файл на месте встроенным форматтером (gofmt-стиль: 4 пробела, без хвостовых пробелов, один `\n` в конце; семантика не меняется, резервная копия не создаётся) |
| `--rule=<имя>` | инлайн | Проверить только указанное правило (единственная опция с формой `=`) |

`--format` — дополнительное действие, а не режим: линтер работает как обычно, порядок применения — сначала фиксы `--fix`, потом форматирование, одной записью на месте. Exit-код `--format` не меняет: он отвечает на вопрос «чист ли файл по правилам», а не «отработал ли форматтер», — форматтер правит только пробелы и warning не чинит. Поэтому `lint --format` на файле с warning выходит 1 при отформатированном файле; толерантный режим — `--fix` (exit 1 только на оставшихся error). Файл с синтаксическими ошибками не форматируется — ошибки парсера печатаются вместо диагностики.

## Примеры

```bash
tsclang lint hello.tsc
tsclang lint hello.tsc --fix
tsclang lint hello.tsc --format
tsclang lint hello.tsc --fix --format
tsclang lint hello.tsc --rule=prefer-const
```

## Коды выхода

- 0 — замечаний нет (или все исправлены `--fix`)
- 1 — есть диагностики (включая warnings) или ошибки парсера
