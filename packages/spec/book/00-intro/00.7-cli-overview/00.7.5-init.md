# 00.7.5 init — создание проекта

## Синтаксис

```bash
tsclang init [имя] [опции]
```

## Описание

Создаёт новый проект. С именем — в новом каталоге `имя/` (создаётся и становится рабочим); без имени — в текущем каталоге, имя пакета по умолчанию `myapp`.

Тип проекта задаётся опциями (при нескольких флагах побеждает последний в приоритете `--platform` > `--library` > `--declaration` > `--type`):

| Опция | Сокращение | Тип | Что создаёт |
|-------|------------|-----|-------------|
| (без флага) | — | `executable` | `tsc.package.json` + `src/main.tsc` (Hello, World) + `test/main.test.tsc` |
| `--type <t>` | — | явный тип | как соответствующий флаг |
| `--library` | `-l` | `library` | только `tsc.package.json` (TSClang-библиотека) |
| `--declaration` | `-d` | `declaration` | только `tsc.package.json` (C-wrapper) |
| `--platform` | `-p` | `platform` | только `tsc.package.json` (профиль платформы) |

Существующие файлы не перезаписываются (`src/main.tsc` и тест сохраняются, если уже есть).

`executable`-проект готов к сборке и запуску (`build --emit exec`) сразу; `test/main.test.tsc` — стартовый пример для `tsclang test`.

## Примеры

```bash
tsclang init myapp                # executable в myapp/
tsclang init mylib --library      # TSClang-библиотека
tsclang init sqlite3 -d           # C-wrapper (declaration)
tsclang init --type library       # библиотека в текущем каталоге
```

## Коды выхода

- 0 — проект создан
- 1 — ошибка записи (нет прав и т.п.)
