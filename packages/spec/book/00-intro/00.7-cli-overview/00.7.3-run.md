# 00.7.3 run — именованные задачи

npm-модель: секция `scripts` в корневом `tsc.package.json` хранит именованные
shell-команды проекта, `tsclang run <name>` выполняет их.

## Синтаксис

```bash
tsclang run            # список скриптов проекта
tsclang run <name>     # выполнить scripts.<name>
```

```json
{
  "name": "blink",
  "version": "0.1.0",
  "type": "executable",
  "main": "src/main.tsc",
  "scripts": {
    "dev":   "tsclang build src/main.tsc --watch --emit exec",
    "build": "tsclang build --build uno",
    "flash": "tsclang build --build uno --emit flash",
    "test":  "tsclang test"
  }
}
```

## Семантика

- Скрипт выполняет shell хоста: `cmd` на Windows, `/bin/sh` на Unix (как
  `--command`, 00.7.2). Синтаксис платформозависим и лежит на совести автора.
- Код выхода скрипта становится кодом выхода CLI: `tsclang run test` в CI
  проваливается ровно тогда, когда провалились тесты.
- Неизвестное имя: `ConfigError: unknown script 'x'; available: ...`, exit 1.
- Без `tsc.package.json` — ошибка `tsclang run: requires a tsc.package.json`.

## `tsclang` внутри скриптов — self-shim

`run` добавляет в `PATH` временную обёртку `tsclang`, вызывающую этот же CLI
(аналог `node_modules/.bin` у npm). Поэтому `tsclang ...` в скриптах работает
без глобальной установки — и всегда вызывает ту же версию CLI, из которой
запущен `run`.

## Dev-цикл

`tsclang run dev` с `"dev": "tsclang build src/main.tsc --watch --emit exec"` —
полноценный цикл разработки: при каждом изменении build пересобирает проект,
завершает дерево прошлого процесса артефакта и запускает новый. Аналогия:
`npm run dev` → vite — hot-reload умеет vite; `run` лишь именует команду.

## Границы: события против имён

| Нужна | Инструмент |
|-------|-----------|
| Тихий запуск программы (`go run`) | `build --emit exec` (00.7.2) |
| Действие после каждой пересборки в watch | `build --watch --command "..."` / `--emit exec` |
| Имя для команды/CI, многошаговый пайплайн, действие без сборки | `scripts` + `tsclang run` |

События сборки (watch, перезапуск артефакта) обслуживает сам `build`; `scripts` —
слой именования поверх. `builds.<name>.command` — «что сделать после этой сборки
автоматически», `scripts` — «что вызывают явно по имени».

## Безопасность

Скрипты читаются только из корневого `tsc.package.json` проекта — манифесты
установленных зависимостей (`tsc_packages/`) не читаются. Уровень доверия —
«скрипты в собственном package.json», как у `builds.<name>.command`.

## Примеры

```bash
$ tsclang run
scripts:
  build
  dev
  flash
  test

$ tsclang run flash
> flash: tsclang build --build uno --emit flash
Flashed main.hex to atmega328p via arduino
```

## Ошибки

```
ConfigError: unknown script 'ghost'; available: build, dev, flash, test
tsclang run: requires a tsc.package.json
```
