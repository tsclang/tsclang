# 00.7.7 validate-config — проверка манифеста

## Синтаксис

```bash
tsclang validate-config <tsc.package.json>
```

## Описание

Проверяет манифест проекта. По порядку:

1. Файл читается и парсится как JSON.
2. Обязательные поля: `name`, `version` (валидный semver).
3. Тип проекта (`type`, по умолчанию `package`):
   - `library` — поле `main` запрещено;
   - `executable` — поле `main` обязательно;
   - для `library` запуск через `tsclang run` недоступен (проверка сообщит об этом).
4. Каждая сборка из `builds` — только допустимые ключи: `target`, `mcu`, `toolchain`, `toolchainFile`, `arch`, `emit`, `linkerScript`, `frequency`/`freq`, `allocator`, `debug`.
5. `strict` — только известные правила (`no-any`, `no-unsafe`, `no-native`, `safe-math`, `no-lossy-cast`, `no-dynamic-alloc`, `no-closures`, `no-sort`).
6. Для `package` с зависимостями — резолв версий: каждая зависимость разрешается в конкретную версию, транзитивные зависимости проверяются на конфликты версий (плоское дерево); прошедший резолв печатается построчно `resolved: <имя>@<версия>`.

В конце печатается сводка: сборки (для единственной embedded-сборки — таргет, mcu и частота), зависимости, таргеты.

## Пример

```bash
tsclang validate-config tsc.package.json
```

## Коды выхода

- 0 — манифест валиден
- 1 — любая из проверок не прошла (сообщение `ConfigError: ...` с причиной)
