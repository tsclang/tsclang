# 00.4.4 CMakeLists.txt

При `tsclang build` с `--emit c` (по умолчанию) автоматически генерируется `CMakeLists.txt`, если он не существует:

```cmake
cmake_minimum_required(VERSION 3.10)
project(hello C)
set(CMAKE_C_STANDARD 11)
set(CMAKE_C_STANDARD_REQUIRED ON)
add_executable(hello hello.c)
target_include_directories(hello PRIVATE "C:/path/to/tsclang/packages/compiler/src/runtime")
```

Разбор:

## `cmake_minimum_required(VERSION 3.10)`

Минимальная версия CMake. TSClang генерирует C11-код, поэтому CMake 3.10+ достаточен.

## `project(hello C)`

Имя проекта — имя файла без расширения. Язык — C.

## `set(CMAKE_C_STANDARD 11)`

TSClang генерирует C11-код (использует `<stdatomic.h>`, `_Static_assert`, etc.).

## `add_executable(hello hello.c)`

Один исходный файл — `hello.c`. Если есть импорты, все модули объединяются в один `.c` файл.

## `target_include_directories(hello PRIVATE "...")`

Путь к `runtime.h`. CLI находит runtime автоматически по расположению `tsclang`-пакета.

## Async и libuv

`CMakeLists.txt` **не** добавляет libuv автоматически — даже для async/await. По умолчанию async-рантайм использует cooperative busy-spin loop и не имеет внешних зависимостей. Libuv подключается только opt-in: если собрать C с макросом `TSC_SCHEDULER_LIBUV` (событийный планировщик поверх libuv), линковку `-luv` нужно добавить в `CMakeLists.txt` вручную — сгенерированный файл не перезаписывается, правьте свою копию.

## Важно

TSClang **не перезаписывает** существующий `CMakeLists.txt`. Если файл уже есть — он используется как есть. Это позволяет кастомизировать сборку.
