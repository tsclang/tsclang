# 00.4.7 Top-level код

TSClang поддерживает **top-level код** — выражения на верхнем уровне файла, без обёртки в `main()`.

```typescript
console.log("Hello, World!");
```

Это эквивалентно:

```typescript
function main(): void {
    console.log("Hello, World!");
}
```

Но писать `function main()` не нужно.

## Что можно на top-level

Любые выражения и объявления:

```typescript
let x: i32 = 42
const name = "TSClang"

function greet(who: string): void {
    console.log("Hello, " + who)
}

greet(name)
console.log("x =", x)
```

Сгенерированный C:

```c
#include "runtime.h"

void greet_string(String who) {
    String _tmp_0 = tsc_string_concat(STR_LIT("Hello, "), who);
    printf("%s\n", _tmp_0.data);
    tsc_string_release(_tmp_0);
}

int main(void) {
    TSC_INIT();
    int32_t x = 42;
    const String name = STR_LIT("TSClang");
    greet_string(name);
    printf("x = %d\n", x);
    tsc_string_release(name);
    return 0;
}
```

Разбор:

### Name mangling

`greet(who: string)` → `greet_string`. Компилятор добавляет суффикс `_string` по типу параметра. Это позволяет перегрузке функций работать в C — `greet(i32)` и `greet(string)` компилируются в разные C-функции.

### tsc_string_concat

`"Hello, " + who` → `tsc_string_concat(STR_LIT("Hello, "), who)`. Конкатенация строк создаёт новую строку. Временная строка `_tmp_0` освобождается через `tsc_string_release` сразу после printf.

### const

`const name = "TSClang"` → `const String name = STR_LIT("TSClang")`. `const` из TSClang сохраняется в C.

### tsc_string_release

`const String name` — это строковый литерал (`capacity = 0`), поэтому `tsc_string_release` — no-op (нет refcount, нет heap). Но компилятор генерирует вызов для единообразия — для heap-строк он был бы необходим.

### Переменные внутри main

Все переменные (`x`, `name`) размещаются **внутри** `main()`, а не на file scope. Это обеспечивает:
- Корректный scope — переменные не утекают в глобальное пространство
- Deterministic cleanup — `tsc_string_release` вызывается в конце main
- RAII-семантику — разрушение в обратном порядке

Функции объявляются **до** `main`. Top-level выражения выполняются **внутри** `main` в порядке объявления.

## Порядок выполнения

1. Функции, классы, интерфейсы → C-определения до main
2. Переменные (let/const на top-level) → локальные переменные внутри main()
3. Выражения на top-level → тело main в порядке объявления
4. Cleanup → `tsc_string_release` для строковых переменных в конце main

## Отличие от TypeScript

В TypeScript top-level код работает в модулях. В TSClang — файл = модуль, top-level код = точка входа.

Если файл содержит только объявления (без top-level выражений) и импортируется — он компилируется как библиотека, без `main`.
