# 00.4.6 Цикл разработки: build --command

`tsclang build --emit binary --command "<cmd>"` — сборка и запуск одной командой. Прежняя
команда `tsclang run` удалена: её случай полностью покрывает пост-билд хук `--command`.

```bash
tsclang build hello.tsc --emit binary --command "./hello"   # Linux/macOS (sh)
tsclang build hello.tsc --emit binary --command ".\\hello"  # Windows (cmd)
```

## Что происходит

1. Читает `hello.tsc`
2. Компилирует в C
3. Записывает `.c` в `--out-dir` (по умолчанию текущий каталог)
4. Вызывает `gcc` для сборки бинарника
5. Выполняет команду в shell хоста (`cmd` на Windows, `/bin/sh` на Unix)
6. Выходит с кодом возврата команды

## Передача аргументов

Аргументы программы указываются прямо в строке команды (прежде — через `run -- arg1 arg2`):

```bash
tsclang build hello.tsc --emit binary --command "./hello arg1 arg2 arg3"
```

## Watch: пересборка + перезапуск

```bash
tsclang build hello.tsc --emit binary --watch --command "./hello"
```

При изменении исходников: пересборка → прежний процесс завершается (всё дерево) → команда
запускается заново. Провалившаяся пересборка не трогает работающий процесс. Полная семантика — 00.7.2.

## Отличие от разовой ручной сборки

| | `--emit binary --command` | `--emit binary` без `--command` |
|---|------|---------|
| Куда пишет | `--out-dir` | `--out-dir` |
| Запускает | Да, после успешной сборки | Нет |
| Код выхода CLI | Код команды | Код сборки |
| Для чего | Цикл разработки | Продакшен-сборка, CI |
