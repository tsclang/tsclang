# 00.4.6 Цикл разработки: build --emit exec

`tsclang build --emit exec` — сборка и запуск одной командой. Прежняя команда `tsclang run`
удалена: её случай — это ступень `exec` на лестнице emit (`c` → `binary` → `exec`).

```bash
tsclang build hello.tsc --emit exec
```

## Что происходит

1. Читает `hello.tsc`
2. Компилирует в C
3. Записывает `.c` в `--out-dir` (по умолчанию текущий каталог)
4. Вызывает тулчейн (кеш платформы или пин) для сборки бинарника (артефакт остаётся на диске)
5. Запускает бинарник прямым spawn по абсолютному пути — без shell, поэтому команда
   одинакова на Linux/macOS и Windows
6. Выходит с кодом возврата программы

## Передача аргументов

Аргументы и окружение программы — часть shell-команды, поэтому для них «выпускаемся»
в `--emit binary --command` (прежде — через `run -- arg1 arg2`):

```bash
tsclang build hello.tsc --emit binary --command "./hello arg1 arg2 arg3"
```

Синтаксис команды платформозависим (`./hello` в sh, `hello.exe`-пути с обратными
слешами в cmd) — полная семантика в 00.7.2.

## Watch: пересборка + перезапуск

```bash
tsclang build hello.tsc --emit exec --watch
```

При изменении исходников: пересборка → прежний процесс завершается (всё дерево) →
программа запускается заново. Провалившаяся пересборка не трогает работающий процесс.

## Отличие ступеней лестницы

| | `--emit exec` | `--emit binary --command` | `--emit binary` |
|---|------|---------|---------|
| Куда пишет | `--out-dir` | `--out-dir` | `--out-dir` |
| Запускает | Да, сам артефакт (без shell) | Да, произвольную команду | Нет |
| Аргументы/окружение | нет (нужны — `binary` + `--command`) | в строке команды | — |
| Код выхода CLI | Код программы | Код команды | Код сборки |
| Для чего | Цикл разработки | Кастомный запуск (аргументы, env, отладчик) | Продакшен-сборка, CI |

`--emit exec` + `--command` вместе — конфликт (exec уже запускает): `ConfigError`, exit 1.
