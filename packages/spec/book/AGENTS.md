# AGENTS.md — книга TSClang: план и рабочий процесс

Инструкции для ИИ, работающего с книгой `packages/spec/book/`. Действуют вместе с корневым `AGENTS.md` и `PLAN.md` (структура книги, шаблон analysis, формат LOG). Источник тем — `TOC.md`.

## Миссия

**Книга — драйвер верификации.** Пишем главы дальше (Блок 0 готов); каждая глава:
сверяется со спекой (`packages/spec/spec/`) и кодом (`packages/compiler/src/`), покрывается
тестами, чинит код/спеку по необходимости. Аудит #205 поглощается: spec-файлы, покрытые
главой, получают маркер `> Spec status: verified @ <hash> · <дата> · #205`.

## Режим работы (решение пользователя, 2026-10-31)

Идём **по одной главе за раз, вместе с пользователем — НЕ автономно**. Цикл главы:

1. **Разведка** — факты из кода и спеки, пробные компиляции, найденные расхождения
   со спекой, спорные места. Приношу пользователю.
2. **Структура главы** — список тем + что показываем в каждой (примеры, C-output, «почему так»).
3. **Обсуждение** — пользователь правит структуру/стиль. Без его подтверждения файлы не пишем.
4. **Исполнение** — файлы тем → corpus-тесты → analysis → LOG/Glossary/TOC → коммит + push.

## Правила исполнения

- Файл темы: `NN.N.N-slug.md`, заголовок `# NN.N.N Название`, стиль как в Блоке 0
  (туториал + reference, ```typescript-примеры, реальный C-output отдельным ```c-блоком).
- Тесты: `packages/tests/test/cases/book/<блок>/<глава>/<name>/` — [R]/[F]/[E] по смыслу
  примера, фрагменты дописываются до полных (PLAN.md). Прогон после каждой главы:
  `pnpm tsx packages/tests/test/runner.ts book` — обязателен зелёным.
- Analysis: `<NN>.analysis.md` по шаблону PLAN.md — каждое утверждение ↔ spec/impl/runtime.
- Расхождения — арбитраж пользователем, по каждому отдельно (вердикты в PLAN.md).
  Спорные дизайн-решения не решать молча — выносить списком в конец главы/сессии.
- Компилятор не меняем без ТДД: красный тест → фикс отдельным коммитом `fix(...) (closes #NNN)`;
  если фикс раскрывается в рефакторинг — issue + error-test (П6 корневого AGENTS.md).
- Спека: контентные правки в коммите главы; маркеры `verified @ <hash главы>` — отдельным
  `docs(spec)`-коммитом (обычно в конце сессии, см. Фазу C).
- Коммит главы: `docs(book): [STABLE] <NN.X название> + tests + analysis (#205)`, push сразу.
- Ручные пробы CLI только с `--outDir .tsclang-tmp/`. Относительные пути, не абсолютные.

## Разведка 01.1 — ключевые факты (чтобы не переоткрывать)

Из `packages/compiler/src/compiler/lexer.ts` (`lex(src, filename)` → `Token[]`,
`Token{type, value, line, col}`, последний токен `EOF`):

- Типы токенов: NUMBER, BIGINT (`42n`, любая база), STRING (`"`), SQUOTE (`'`), BOOL, NULL,
  IDENT, TEMPLATE (backtick с `${}`), пунктуация, операторы. Совпадения — maximal munch:
  `>>>=` проверяется раньше `>>>`, тот раньше `>>=`.
- Ключевые слова остаются типом IDENT (набор KEYWORDS); исключения: `true`/`false` → BOOL,
  `null`/`undefined` → NULL, причём value нормализуется в `'null'` — синонимы уже в лексере.
- **Перенос строки НЕ терминирует стейтменты**: `eatSemi()` = `tryEat(SEMI)`, выражения
  парсятся жадно через переводы строк. `return\n5` → `return 5` (в JS ASI дал бы `return; 5`).
  `x\n++x` → `x++` (постфикс через перенос). Книга 00.4.1 «это не ASI» права;
  **спека 02-formatting называет это ASI и «вставляет ;» — механизм описан неверно**,
  наблюдаемая таблица символов-продолжений верна. Поправить спеку в главе 01.3.
- Ошибки лексера — без E-кодов, формат `file:line:col: msg`: `Unterminated string`,
  `Unterminated template literal/expression`, `legacy octal notation is not supported;
  use 0o prefix` (для `0777`), `bigint literal must be an integer`, `Unexpected character: "£"`.
- `#[...]` — лексер даёт HASH, парсер даёт SyntaxError c help «replace #[target(avr)]
  with: --target avr (CLI) or {"target":"avr"} in tsc.package.json» (parser.ts:352).
- Комментарии `//` и `/* */` — **без вложенности** (скан до первого `*/`).
- Идентификаторы: **юникод поддержан** (реализовано! см. ниже, #230). Старт `\p{L}_$`,
  продолжение `\p{L}\p{N}\p{M}_$` — эмодзи/£ невалидны, как в JS/TS.
- Одинарные кавычки: `'hello'` без аннотации → `String` (спека 02-formatting права,
  «одинарные = двойные»); `'A'` с аннотацией char/u8 → код символа. Уточнить правила в 01.5.
- Числа: `0x`/`0b`/`0o` + `_`-разделители (срезаются в лексере); дробная часть — только
  если после точки цифра (поэтому `1..2` → NUMBER DOTDOT NUMBER — диапазон); `e/E`-экспонента.
- Юникод в строках и комментариях — ок (UTF-8 passthrough); в идентификаторах — теперь тоже.

## Реализовано вне книги: unicode identifiers (#230, 36542fb4)

Решение пользователя (арбитраж 01.1.6 снят): юникод-идентификаторы реализованы,
а не задокументированы как отклонение. Лексер `\p{L}`/`\p{L}\p{N}\p{M}`; новый pass
`rename-unicode.ts` (после семантики, до codegen) манглит в ASCII: `цена` →
`u0446u0435u043du0430`, `café` → `cafu00e9`, `𝒳` → `u01d4b3` (6 hex для астральных),
`a$b` → `au0024b` (заодно фикс латентного бага с `$` в C). Спека — новый
`02-syntax/02-identifiers.md`; 8 кейсов в `02-syntax/identifiers/`; полный корпус зелёный
(2026-11-03). Глава 01.1.6 пишет по реализации. Коллизии с литеральными `u0446`-именами —
документированы, не запрещаются (П2).
