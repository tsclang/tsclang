# Дизайн-философия

## Иерархия приоритетов

При любом дизайн-решении — иерархия приоритетов:

1. **Безопасность памяти** — ownership, borrow checker, детерминированное освобождение
2. **Производительность и типизация** — zero-cost abstractions, строгая типизация
3. **TS-синтаксис** — максимально сохранять, но не ценой п.1 и п.2

Приоритет 3 означает: при выборе КАК выразить концепцию, TS-синтаксис предпочтительнее Rust, C, Go и других языков. Но сам синтаксис уступает безопасности и производительности.

## TS-совместимый синтаксис

Новые концепции встраиваются через TS-совместимый синтаксис:

| Концепция | TSClang | Rust |
|-----------|---------|------|
| Immutable borrow | `Ref<T>` | `&T` |
| Mutable borrow | `Mut<T>` | `&mut T` |
| Классы | `class` | — (struct + impl) |

Вопрос при каждом решении: *можно ли выразить это через существующий TS-синтаксис или его естественное расширение?*

## Обратная совместимость

Цель не "существующий TS-код компилируется без изменений", а "TS-разработчик узнаёт синтаксис и чувствует себя дома".

### Работает как есть

- Классы, объекты, массивы, циклы
- Template literals, стрелочные функции
- Деструктуризация, spread-оператор
- `if`/`else`, `switch`, `while`, `for`

### Требует правок

- Смешанные массивы: `[1, "a"]` → нужна явная аннотация типа
- `native` выражения: нельзя вывести тип из C

### Не переносится из TS

| TS-фича | TSClang | Причина |
|---------|---------|---------|
| `any` | Ограничен (strict rule `no-any`) | Нарушает типизацию |
| `undefined` | Синоним `null` | Упрощение модели |
| `var` | Синоним `let` | Нет hoisting/TDZ |
| `typeof` | Только compile-time | Нет runtime reflection |
| `delete` | Нет оператора | Ownership не позволяет |
| `===` / `!==` | Синонимы `==` / `!=` | Нет type coercion в TSClang |

### Пример

```typescript
// Работает как есть:
let a = 10              // type inference → number
let b = undefined       // undefined = null (синоним)

class User {
  name: string = ""
  age: number = 0
}

// Требует правок:
throw "error"           // → throw new Error("error")
export default function // → export function()
```
